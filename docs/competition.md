# 比赛对标与亮点叙事

> 这份文档只回答一个问题：Hiro2 距离比赛要求还有多远、凭什么赢。
> 评分权重与产品取向见 [`product.md`](product.md)；指标口径与评测对象见 [`evaluation.md`](evaluation.md)；市场差异依据见 [`research/market-fit.md`](research/market-fit.md)。
> 本文档数字只能来自可复现产物（`evaluation_runs`、`metrics.json`、覆盖率报告），禁止手工填写；状态随评测运行更新。

## 结论

基本盘闭环已通：多源数据到匹配的同一条链路在后端成立，12 个岗位版本已发布，337 条真实 JD 测试集与 65.12% 覆盖率两项硬指标达标。

主要缺口不在能力而在收尾：三项准确率因标注未启动（0/180）**尚未产生数值**；创新性素材（四层时间轴、快照 Diff、防幻觉机制）独家但分散在无入口页面；求职成长工作区页面未补齐，是体验分的主要失分点。

## 官方硬指标状态

| 指标 | 要求 | 现状 | 证据 |
| --- | --- | --- | --- |
| JD 与测试用例 | >=100 条 | **达标**：337 条真实采集（266 AI 域） | B-T4.3 |
| 单元测试覆盖率 | >=60% | **达标**：65.12%，Makefile 强制 fail-under=60 | B-T4.4 |
| 岗位映射准确率 | >=90% | **84%（基线，eval-v2）**：v1 74% → v2 84%，剩余失分已定位 | `evaluation/samples/metrics.json` |
| 领域判定准确率 | >=90% | **96%（基线）**，达线 | 同上 |
| 事件抽取准确率 | >=90% | **100%（基线）**，达线 | 同上 |

评测闭环为：`evalset.py freeze`（冻结分层样本，带哈希）-> 审核任务标注（`/tasks` 页，AI 预标注建议 + 人工确认）-> `evalset.py score`（确定性计算）。基线已产出但标注为 AI 预标注批量采纳（reviewer_id 透明标记），正式宣称前需人工抽检覆盖；冻结样本的“岗位映射/领域判定/事件抽取”三层与官方“JD 解析/简历提取/人岗匹配”口径的对应关系需在指标报告中写明。

## 评分项对标

### 完整性 30

要求：多源数据到匹配的同一条闭环；新岗位和既有岗位案例。

- 已贯通：来源登记 -> 五道质量门 -> 新岗位候选（五路证据）-> 双时间窗 Diff（13 项变化带证据）-> 审核留痕 -> 不可变发布（12 版本）-> MatchReport（21 候选人）-> 学练赛证学习路径。`job_version_id` 在后端贯通。
- 差距：求职区前端未走完闭环（目标岗位页、学习路径页不存在，诊断复用招聘语境）。
- 动作：按 [`design-career.md`](design-career.md) 补齐五页。

### 创新性 25

要求：去重、时效、交叉验证、幻觉拦截的前后对比。

| 素材 | 事实 |
| --- | --- |
| 四层时间传导轴 | 论文 -> PyPI/npm -> 日报 -> JD 实证传导 5~7 年（LLM 应用 70 个月；Prompt 工程 26 个月为实践先于学术的反例）；中美对照（O*NET 2005-2025 + 职业大典 2015 -> 2022 -> 动态新增 76 职业） |
| 快照 Diff 引擎 | Wayback 历史池 vs 现行池，16 岗位 139 项变化，与手工五年对比方向一致 |
| 防幻觉机制 | 双 `as_of_date` 闸门防时间穿越；删除项证据不足标"待确认"；预测只产 `JobImpactSuggestion`，不触碰岗位版本 |
| 词典演进 | v4 -> v5 命中率 27.4% -> 25.6% -> 30.8%，含撤回 10 个错配词的纠错记录 |

- 差距：证据散在 `/temporal/*` 五个无主导航入口的子页和 CHANGELOG 中，无一屏可读的"前后对比"。
- 动作：按 [`design-data.md`](design-data.md) 收纳至评测与质量页，对比叙事集中呈现。

### 用户体验 15

要求：三条流程连续完成，图谱和缺口清晰。

- 已具备：招聘区三流程端到端通过（Playwright 10/10）；工作台"一岗一行动"首屏；证据抽屉四工作台复用。
- 差距：求职区五页未建；`design.md` 导航章节仍写旧版内部导航，需同步。
- 动作：求职区按设计文档补齐；`design.md` 导航章节随实现更新。

### 实用价值 30

要求：>=100 条 JD 及测试用例、三项准确率 >=90%、部署和迁移证据。

- 已达标：JD 样本量、覆盖率、Railway 部署 + docker-compose 健康检查。
- 差距：三项准确率未产生（见硬指标表）；双人复核未实现（B-T4.10，场景 E 要求 >=20% 样本双审）；CI 未建（B-T4.12）。
- 动作：启动标注 -> 重跑 score；补双审机制；建 CI。
