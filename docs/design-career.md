# 求职成长工作区设计

## 服务对象

新兴领域青年、新就业形态劳动者和希望转入 AI 相关岗位的求职者。该角色使用已发布岗位版本判断能力差距并制定可执行的提升路径。

## 首要任务

```text
选择目标岗位 -> 确认能力画像 -> 查看关键缺口 -> 获取学习路径 -> 形成能力证明
```

该角色不参与岗位定义、证据审核和岗位版本发布。

## 入口与导航

首次进入时提供任务选择：

```text
[选择目标岗位] [上传简历开始诊断]
```

求职成长工作区导航：

```text
首页 / 目标岗位 / 我的画像 / 人岗诊断 / 学习路径
```

企业招聘和内部审核入口不出现在该角色的主导航中。

## 首页首屏

首屏先展示行动结果，不展示内部系统信息：

```text
目标岗位：AI Agent 工程师 v2
匹配基础：82%
必备能力：7/8
优先补齐：Prompt 工程、多模态 AI、ML/DL 算法
[继续诊断]
```

如果尚未选择岗位，首屏只展示目标岗位选择和简历上传入口，不显示空的图谱或质量指标。

## 目标岗位页面

首屏回答：有哪些岗位值得投、我离哪个最近。

```text
顶：技术栈筛选（AI / 大数据 / 智能系统 / 物联网）
中：岗位卡列表
底：选中岗位的职责展开与“开始诊断”
```

岗位卡只展示求职决策需要的信息：

```text
岗位名称 / 核心职责 / 必备能力数 / 你的匹配基础 / 开始诊断
```

规则：

- 岗位卡按与当前画像的匹配基础排序；未建画像时按岗位热度排序并提示先建画像。
- 岗位变化、日报信号和审核状态属于岗位详情的次级信息，不作为求职者的首屏内容。
- 只列已发布岗位版本；卡片固定显示版本号，保证诊断可回溯。

## 人岗诊断流程

顶部固定上下文：

```text
目标岗位：AI Agent 工程师 v2
当前阶段：确认能力画像
下一步：确认技能后查看匹配结果
```

流程步骤：

```text
选择岗位 -> 上传简历/填写能力 -> 确认识别结果 -> 查看差距
```

主页面布局：

```text
左：我的画像（技能、熟练度、项目，可修改）
中：匹配结果（必备达成 / 已具备 / 部分具备 / 缺失数量，优先补齐三项置顶）
右：匹配理由（每项判断对应的岗位要求与你的经历依据）
```

首屏优先展示：

1. 必备能力是否达到基础要求；
2. 已具备、部分具备、缺失的数量；
3. 最需要优先补齐的三项能力；
4. 重新计算匹配按钮。

总分不能遮蔽必备能力缺口，也不能生成自动录用或淘汰结论。

## 我的画像

首屏回答：系统认识的我是否准确、我改了什么。

```text
技能列表：技能 / 熟练度 / 年限 / 来源（简历解析或手工）/ 状态
项目与证书：项目说明、证书、行业经验，可增删改
修正记录：每次修改的时间与内容（对应 user_corrections）
```

规则：

- 简历解析结果先进入待确认状态，求职者确认后才计入画像。
- 无法标准化的技能显示“待确认”，不计入已具备；可手工归并到标准技能。
- 画像修改后，所有引用该画像的诊断报告提示“可重新计算”。

## 缺口与学习路径

学习路径是独立页面，顶部固定目标岗位与版本上下文。每项缺口必须说明：

```text
缺什么 / 为什么重要 / 先后顺序 / 如何练习 / 如何证明
```

学习路径统一使用“学练赛证”：

```text
学：核心知识点
练：项目或工作流练习
赛：测试集、实践评测或复盘
证：项目说明、结果记录和可验证证据
```

例如：

```text
01 Prompt 工程
先补基础，因为它是智能体工作流的前置能力
完成一个多步骤工作流并通过测试集
```

## 能力修正

求职者可以修改熟练度、年限、项目经历和技能是否具备。修改后的主按钮使用“重新计算匹配”，不使用“运行”“提交模型”等技术术语。

无法标准化的技能显示为“待确认”，不能计入已具备；简历解析失败时保留原文件并提供手工录入入口。

## 证据表达

求职者看到的是可理解的证据：项目经历、技能来源、岗位要求和匹配理由。run_id、数据集版本、模型版本和内部审核记录放入可选的详情区域。

## 权限边界

求职者可以管理自己的画像、项目和诊断记录，可以查看已发布岗位版本和学习路径；不能编辑岗位要求、审核岗位变化或查看其他人的简历和内部质量数据。

## 验收标准

- 用户无需阅读产品说明即可开始选择目标岗位；
- 首屏能回答“是否具备投递基础”和“先补什么”；
- 每项缺口都有理由、顺序、练习和证明方式；
- 用户修正画像后能明确看到重新计算结果；
- 页面不展示自动录用/淘汰结论，不把内部技术字段当作主信息。

## 数据接入原则

求职成长工作区的岗位、能力要求和诊断结果必须来自已发布岗位版本 API；个人画像可以来自用户上传或受控的合成测试样本。岗位趋势和学习建议只能使用已审核或已发布事实，不能把预测 fixture 当作招聘要求。
