# 求职工作区设计

## 服务对象

新兴领域青年、新就业形态劳动者和希望转入 AI 相关岗位的求职者。该角色使用已发布岗位版本判断能力差距并制定可执行的提升路径。

## 首要任务

```text
选择目标岗位 -> 确认能力画像 -> 查看关键缺口 -> 获取学习路径 -> 形成能力证明
```

该角色不参与岗位定义、证据审核和岗位版本发布。

## 入口与导航

切换到求职工作区后直接进入目标岗位页。求职工作区导航：

```text
目标岗位 / 我的画像 / 人岗诊断 / 学习路径 / 简历工作台
```

企业招聘和内部审核入口不出现在该角色的主导航中。
求职者诊断固定使用 `/career/diagnosis`，招聘侧候选诊断固定使用 `/diagnosis`；角色视图由 URL 决定，不读取本地状态推断。

## 目标岗位页面

首屏回答：有哪些岗位值得投、我离哪个最近。

```text
顶：技术栈筛选（AI / 大数据 / 智能系统 / 物联网）
中：岗位卡列表
底：选中岗位的职责展开与“开始诊断”
```

岗位卡只展示求职决策需要的信息：

```text
岗位名称 / 核心职责 / 必备能力数 / 你的匹配基础 / 开始诊断
```

规则：

- 岗位卡按与当前画像的匹配基础排序；未建画像时按岗位热度排序并提示先建画像。
- 岗位变化、日报信号和审核状态属于岗位详情的次级信息，不作为求职者的首屏内容。
- 只列已发布岗位版本；卡片固定显示版本号，保证诊断可回溯。

## 人岗诊断流程

目标岗位和版本放在诊断结果标题区，与岗位选择控件相邻。页面不增加全局“当前阶段 / 下一步”横条；下一步动作只在画像保存、重新诊断和学习路径等实际操作位置出现。

流程步骤：

```text
选择岗位 -> 上传简历/填写能力 -> 确认识别结果 -> 查看差距
```

主页面布局：

```text
左：我的画像摘要（技能、熟练度、项目，只读；编辑进入“我的画像”）
中：匹配结果（必备达成 / 已具备 / 部分具备 / 缺失数量，优先补齐三项置顶）
右：后续行动（进入学习路径）
```

首屏优先展示：

1. 必备能力是否达到基础要求；
2. 已具备、部分具备、缺失的数量；
3. 最需要优先补齐的三项能力；
4. 重新计算匹配按钮。

总分不能遮蔽必备能力缺口，也不能生成自动录用或淘汰结论。

## 我的画像

首屏回答：系统认识的我是否准确、我改了什么。

```text
技能列表：技能 / 熟练度 / 年限 / 来源（简历解析或手工）/ 状态
项目与证书：项目说明、证书、行业经验，可增删改
修正记录：每次修改的时间与内容（对应 user_corrections）
```

规则：

- 简历解析结果先进入待确认状态，求职者确认后才计入画像。
- 无法标准化的技能显示“待确认”，不计入已具备；可手工归并到标准技能。
- 画像修改后，所有引用该画像的诊断报告提示“可重新计算”。

## 缺口与学习路径

学习路径是独立页面，目标岗位与版本作为标题的辅助信息呈现。每项缺口必须说明：

```text
缺什么 / 为什么重要 / 先后顺序 / 如何练习 / 如何证明
```

学习路径统一使用“学练赛证”：

```text
学：核心知识点
练：项目或工作流练习
赛：测试集、实践评测或复盘
证：项目说明、结果记录和可验证证据
```

例如：

```text
01 Prompt 工程
先补基础，因为它是智能体工作流的前置能力
完成一个多步骤工作流并通过测试集
```

## 能力修正

求职者只在“我的画像”修改熟练度、年限、项目经历和技能是否具备。修改后的主按钮使用“保存并重新诊断”，不使用“运行”“提交模型”等技术术语。人岗诊断页只展示画像摘要，不提供第二套编辑入口。

无法标准化的技能显示为“待确认”，不能计入已具备；简历解析失败时保留原文件并提供手工录入入口。

## 证据表达

求职者看到的是可理解的证据：项目经历、技能来源、岗位要求和匹配理由。run_id、数据集版本、模型版本和内部审核记录放入可选的详情区域。

## 权限边界

求职者可以管理自己的画像、项目和诊断记录，可以查看已发布岗位版本和学习路径；不能编辑岗位要求、审核岗位变化或查看其他人的简历和内部质量数据。

## 验收标准

- 用户无需阅读产品说明即可开始选择目标岗位；
- 首屏能回答“是否具备投递基础”和“先补什么”；
- 每项缺口都有理由、顺序、练习和证明方式；
- 用户修正画像后能明确看到重新计算结果；
- 页面不展示自动录用/淘汰结论，不把内部技术字段当作主信息。

## 简历工作台（/career/resume，2026-08-29 V1）

求职闭环最后一块：诊断 -> 成长 -> 证明 -> 投递材料。双栏布局：左侧结构化草稿编辑
（基本信息/概述/技能/经历/项目/教育，增删行）+「生成 PDF 预览」（pandoc + PyMuPDF
Story，与合成测试集同渲染链路，可下载）；右侧建议栏随目标岗位切换。

建议为 V1 确定性层（零 LLM），每条带证据：
- coverage：目标岗位版本必备/加分技能在草稿技能区未体现（severity 按必备/加分，
  evidence 带市场权重与 JD 数）；
- specificity：已具备技能域反查 SKILLS.yml 技能点，提示可具体化方向；
- structure：缺概述/经历 bullet 过少/无量化数字。
边界：V1 只归一显式技能字段，正文 bullet 不做抽取；LLM 表述改写建议为 V2
（结构化输出 + 采纳留痕，遵循 AI 产候选人发布原则）。

## 数据接入原则

求职工作区的岗位、能力要求和诊断结果必须来自已发布岗位版本 API；个人画像可以来自用户上传或受控的合成测试样本。岗位趋势和学习建议只能使用已审核或已发布事实，不能把预测 fixture 当作招聘要求。
