# 数据工作区设计

> 这份文档只回答一个问题：数据工作区的每个页面为谁服务、首屏回答什么问题、信息如何组织。
> 共享视觉、组件和密度规则见 [`design.md`](design.md)；指标口径见 [`evaluation.md`](evaluation.md)；API 字段见 [`contracts.md`](contracts.md)。

## 服务对象

内部质量角色（数据标注员、领域审核员、评测同学）和验收/答辩评审。企业负责人与求职者不进入本区。

本区同时承担两种使用方式：

| 使用方式 | 用户 | 路径 |
| --- | --- | --- |
| 日常工作 | 审核、标注、评测同学 | 审核任务为主入口，高频、有写操作 |
| 只读参观 | 评审 | 总览 -> 评测与质量，两次点击内到达任一评分证据 |

## 首要任务

```text
数据从哪来 -> 处理是否成功 -> 结论是否准确 -> 人工审核是否完成
```

本区是岗位结论的可信性证据中心：招聘与求职工作区消费的每一条岗位事实，都必须能在本区回溯到来源、处理运行、评测指标或审核记录。

与业务工作区相反，`run_id`、数据集版本、样本量、时间戳在本区是一等信息，不作为次级详情隐藏。

## 定位与边界

- 本区只读为主，唯一写操作是审核任务中的决策提交（接受/修改/拒绝/无法判断）。
- 预测、回测和信号只作为证据与建议呈现；岗位版本的发布动作只发生在招聘工作区，本区不提供入口。
- 合成数据必须带 `SYNTHETIC` 标记，不得与正式市场证据视觉混同。
- 评测指标只能来自 `evaluation_runs`，禁止手工填写或硬编码。

## 入口与导航

顶栏工作区切换标签保持"数据"。比赛版区内导航五项：

```text
总览 / 数据资产 / 证据审核 / 评测质量 / 趋势洞察
```

收纳与合并规则：

- 数据集与来源通道合并为数据资产的两个视图。
- 审核任务与证据检索合并为证据审核的两个视图。
- 处理运行不占一级导航，从总览、数据集版本和证据详情进入。
- 市场信号、技术传导和当前预测合并为趋势洞察；岗位影响进入审核任务，预测复盘进入评测质量。

## 总览页（`/data`）

首屏回答：**系统里有多少数据、是否健康、支撑了什么结论。**

```text
KPI 条：总记录数 / 今日处理（成功·进行中）/ 就绪数据集 / 待处理记录
数据流转图：来源 -> 处理 -> 服务对象（节点可点击，打开来源明细抽屉）
```

规则：

- 评分证据速览只放缩略值和跳转，完整指标、数据集隔离说明和错误案例只出现在评测与质量页；同一数值不重复两处主要表达。
- 流转图节点状态非常态时才追加显示；正常状态不重复"可用"等冗余标签。
- 空态说明下一步（"先运行 `make db-import`"），不用空白伪装简洁。

### 表格规范

来源、流水线、数据集目录和趋势预测统一使用语义化表格结构。共用 `.t-table`：
固定列宽、表头粘性定位、正文 16px、表头与辅助字段 14px、数字列右对齐并使用
等宽数字。正文不画逐行横线，只保留表头底线、悬停背景和必要的外框。

窄屏保留可读列宽并允许横向滚动，不通过缩小字号压缩列。可点击行必须支持鼠标、
Enter 和空格键，并提供焦点轮廓；首列使用行标题语义。预测列表不得退回到无表头的
视觉模拟列表，字段名称必须能被辅助技术读取。

## 数据资产页（`/data/assets`）

首屏回答：**系统有哪些数据、从哪里来、当前是什么版本。**

```text
数据集视图：数据集 / 类型 / 主记录数与口径 / 当前版本 / 来源数 / 状态 / 更新时间
来源视图：来源通道 / 类型 / 所属数据集 / 采集模式 / 时间范围 / 使用许可
点击行 -> 右侧抽屉：概览 / 版本历史 / 来源 / 技术信息
```

规则：

- 通道明细来自 `SOURCES.yml` 登记，不写死数字。
- 派生（evidence）、受控（resumes）、冻结（evaluation）数据集显示派生说明，不虚构采集通道。
- 历史回填必须标记 `backfill`，不与实时采集混排。
- 数据集主记录数必须带 `count_scope`，处理阶段数量通过 `stage_counts` 展开；招聘岗位主口径为已解析入库岗位，不再用 70 条标准化样本代表全部 JD。
- 点击数据集可先查看快速抽屉，再进入 `/data/assets/{dataset_id}` 完整档案；内部统一为概览、版本、血缘、字段质量和记录五个视图。
- 简历档案的记录视图展示全部测试简历，支持文件名、样本性质、格式和解析状态筛选；合成、脱敏、上传和受控导入必须可区分，单份简历提供结构化画像、文档预览和处理信息。
- 合成测试集按24个逻辑案例、PDF/DOCX/TXT三种格式组织；每个案例解析一个代表文件，其余格式显式标记“共享画像”。当前72份档案均已具备画像，其中19份使用技能词典基础解析，44份共享同案例画像，9份来自模型解析。

## 流水线页（`/data/pipeline`）

首屏回答：**最近一次处理是否成功、失败在哪、产出质量如何。**

```text
四阶段流转条：采集 -> 抽取 -> 证据 -> 信号（各阶段最近运行时间与计数）
运行表：run_id / 组件 / 阶段 / 状态 / 耗时 / 数量摘要 / 开始时间
```

规则：

- `RUNNING` 超过 30 分钟无终态事件显示"疑似中断"，不与真实进行中混淆。
- 失败行展开显示 `error_type`、`error_message` 摘要和重试次数；堆栈细节进详情，不上表格。
- 点击行打开运行详情（`data/runs/<run_id>/` 的 events 摘要），审核者无需进入文件系统。

## 证据审核页（`/tasks`）

首屏回答：**有什么任务待判断、结论依据具体是什么。**

内部视图：

```text
证据库 / 审核任务
```

默认进入证据库；只有显式选择审核任务或从待审核建议进入时切换到任务视图。

```text
左：任务列表（类型 / 优先级 / 数据来源 / 运行版本 / 状态，"需双审"标记）
右：三栏工作区
  原文与来源证据 | 系统抽取/预测结果 | 人工决策（接受 / 修改 / 拒绝 / 无法判断）
底：时间、run_id、数据集版本、任务状态
```

规则：

- 审核者全程不离开浏览器，不需要下载数据包或阅读 Agent Trace。
- 提交前显示修改摘要；提交后显示任务状态和是否需要双人复核。
- 任务状态机：待领取 -> 审核中 -> 已提交 -> 已完成；分歧自动创建复核任务，保留全部观点。
- 本页是本区唯一写操作页面；决策按钮复用共享 `ReviewActions`。
- 证据库使用后端分页，默认每页 50 条；支持来源、声明类型、审核状态和关键词筛选，点击记录打开完整证据详情。

## 评测质量页（`/evaluation`）

首屏回答：**系统结论准不准、凭什么信。**

```text
官方硬指标卡：JD 解析 / 简历技能提取 / 人岗匹配 三项准确率 vs 90% 目标
              + 测试 JD 数（>=100）+ 单元测试覆盖率（>=60%）
亮点指标条：证据覆盖率 / 审核一致性 / 岗位变化命中率 / 预测提前量
人工审核质量：任务完成率 / 双人复核率 / 平均响应时长 / 分歧记录
运行对比：新旧 evaluation_runs 指标对比 + 数据集版本
错误分布：错误类型排序 + 可展开的错误案例（输入、预期、实际、人工判定）
```

规则：

- 指标口径与最小验收以 [`evaluation.md`](evaluation.md) 为准，本页只负责呈现，不重新定义。
- 每个指标卡可展开到贡献它的 `evaluation_runs`（运行版本、数据集版本、样本量），再展开到错误案例。
- 前后对比（当前运行 vs 基线、词典版本变更）是本页核心叙事，不分散到多页。
- 未达到目标的指标如实显示当前值与差距，不隐藏。
- 预测复盘作为“预测质量”分类并入本页，不再保留独立路由。

## 趋势洞察（`/temporal`）

首屏回答：**某个能力域正在如何变化、依据是什么、影响哪些岗位。**

```text
能力域排行 | 当前结论 | 技术传导 | 近期依据 | 岗位影响
```

规则：

- 近期依据只显示选中能力域的代表信号；完整 6,130 条唯一信号进入证据库筛选。
- 技术传导在同一页面展示论文 -> 生态包 -> 行业传播 -> JD，不再拆成独立页面。
- 岗位影响只显示待审核状态和去向，实际判断进入证据审核，发布仍发生在招聘工作区。
- 预测质量、基线比较和错误案例进入评测质量。

## 权限边界

- 内部质量角色：查看本区全部页面，在审核任务页提交决策。
- 评审/访客：只读，不进入审核任务提交。
- 企业负责人与求职者：不进入本区；他们需要的可信性信息（证据、版本、审核状态）以证据抽屉形式在业务页面内提供。

## 验收标准

- 评审从总览出发，两次点击内到达任一官方硬指标及其错误案例。
- 任一岗位结论可从业务页证据抽屉回溯到本区的来源通道与处理运行。
- 三项硬指标、测试样本量和数据集版本同屏可读，且可回链 `evaluation_runs`。
- 审核任务从领取到提交全流程在浏览器内完成，每条反馈绑定 `case_id` 与 `run_id`。
- 前后对比（运行对比、基线对比、词典版本）在一屏内可读，不分散在多页。
- 合成数据、历史回填、待审核建议在任一页面均可被视觉区分。

## 数据接入原则

- 全部页面消费 `contracts.md` 定义的展示模型，不直连数据库或读取原始文件。
- 指标类数据以 API 返回为唯一来源；API 不可用时显示空态或错误态，不用 fixture 冒充正式指标。
- mock 模式只用于显式的空态、错误态、离线测试和前端单元测试。
- 大数字必须带单位、时间窗口和口径入口；无口径说明的指标不上屏。
