# Hiro2 前端设计参考

> 这份文档回答一个问题：哪些外部设计方法值得迁移到 Hiro2，应该如何转化为结构化 AI 工作台的实现规则。它不是素材收藏夹，也不替代 [`design.md`](design.md) 的正式 Token 和组件契约。
>
> 调研时间：2026-08-24。外部网站的版本、排名和页面内容会变化；本文件记录的是可复用的设计机制，不把外部页面当作 Hiro2 的事实来源。

## 结论

Hiro2 应采用“证据工作台 + Hybrid UI”的方向：

```text
传统 GUI 任务流程
  + 上下文 AI 意图
  + 可审计执行状态
  + 结构化结果
  + 人工确认和版本发布
```

现代感来自信息组织和反馈速度，而不是聊天气泡、渐变、发光或复杂的全屏动效。主界面应帮助用户快速回答四个问题：

```text
AI 做了什么？
依据是什么？
哪些地方不确定？
我下一步能确认或修改什么？
```

## 调研范围

| 来源 | 主要价值 | Hiro2 的使用边界 |
| --- | --- | --- |
| [Awwwards Interaction Design](https://www.awwwards.com/websites/interaction-design/) | 视觉层级、交互反馈、动效完成度 | 只迁移局部反馈和节奏，不照搬营销型叙事 |
| [SiteInspire](https://www.siteinspire.com/websites) | 编辑式布局、网格、字体和页面密度 | 参考布局和内容节奏，不把作品集首屏当工作台 |
| [Mobbin](https://mobbin.com/) | 真实产品的页面、组件和用户流程 | 优先参考筛选、抽屉、表单、空状态和完整流程 |
| [Ant Design 6](https://ant.design/) | 企业级基础组件、主题和语义结构 | 作为基础组件事实来源，不平行重写 Button/Table/Form |
| [Ant Design X](https://x.ant.design/) | AI 的唤醒、表达、确认和反馈组件 | 作为 AI 交互层，不把 Hiro2 做成聊天产品 |
| [Vercel AI SDK](https://vercel.com/docs/ai-sdk) | 结构化输出、工具调用、流式 UI 数据 | 参考结构化结果和事件流，不替换 Hiro2 的后端边界 |
| [Linear Docs](https://linear.app/docs/parent-and-sub-issues) | 命令入口、上下文操作、低摩擦工作流 | 参考快捷操作和局部编辑，不复制其产品语义 |

## 平台观察

### Awwwards：看反馈，不看页面类型

Awwwards 的 Interaction Design 分类强调动态交互、响应反馈、复杂导航和数据可视化。样本通常具有强烈的首屏叙事、滚动转场、鼠标响应和品牌化视觉。这些做法适合观察“用户动作之后界面如何回应”，但不适合直接作为 Hiro2 的页面骨架。

**可迁移：**

- 选择、聚焦、加载、完成和错误都应该有明确的局部反馈。
- 动效应连接前后状态，例如新增技能从候选区移动到差异行，而不是独立播放装饰动画。
- 复杂内容可以先显示一个清晰的主状态，再渐进展开细节。

**不迁移：**

- 全屏 Hero、滚动讲故事、炫技型 WebGL、自动播放视频和大面积装饰文字。
- 用运动和视觉冲击替代来源、置信度和审核状态。

### SiteInspire：学习编辑式密度

SiteInspire 的网站目录提供 Popular Categories、Styles、Types、Subjects 和 Platforms 等筛选维度，卡片以缩略图、标题、时间和创作者组成清晰的浏览节奏。它的价值在于观察内容如何分组和排列，而不是模仿作品集风格。

**可迁移：**

- 使用稳定网格和明确的内容分组，避免每个区域都变成独立卡片。
- 让筛选状态和结果数量保持同一视觉上下文。
- 通过字体、结构线和间距建立层级，而不是添加更多说明文字。

**不迁移：**

- 以图片缩略图为核心的展示模式。
- 为了视觉节奏而故意制造大片空白，或把业务数据压缩成不可读的装饰数字。

### Mobbin：学习真实流程

Mobbin 将参考拆成 Screens、UI Elements、Flows 和 Text in Screenshots，并覆盖 Settings、Sidebar、Progress Indicator、Dialog、Searching、Onboarding 等真实模式。它还强调按完整用户旅程查看交互，而不是只看单张截图。

**可迁移：**

- 先为每条核心流程建立状态图，再决定页面组件。
- 对话框、抽屉、底部面板和侧栏只在改变任务上下文时使用。
- Loading、Progress、Empty、Error 和完成态必须是同一流程的连续状态。
- 参考真实产品的短文案和动作位置，减少解释性文本。

**不迁移：**

- 移动端模式直接复制到桌面三栏工作台。
- 把“聊天”作为所有 AI 功能的默认入口。

## AI 交互模式

### 1. Do 为主，AI 作为上下文工具

Hiro2 的默认模式应是 `Do + AI 辅助`：用户先选择岗位、版本、时间窗或候选人，AI 再在当前上下文中执行任务。

```text
选择岗位更新窗口
  -> 点击“分析变化”
  -> 显示来源读取和聚合进度
  -> 输出新增 / 删除 / 修改
  -> 查看证据
  -> 接受、修改或拒绝
```

### 2. 对话只表达意图，不承载事实

对话适用于“解释变化”“查找反证”“比较两个来源”等不适合固定控件的意图。对话结果必须转成稳定的业务对象：`JobChangeSet`、`EvidenceView`、`MatchReport` 或 `JobImpactSuggestion`。

禁止让用户从长篇 Markdown 或聊天记录中手工提取岗位字段。

### 3. 过程显示事件，不显示隐藏思维链

AI 过程只显示可审计事件：阶段、工具、输入数量、输出数量、耗时、错误和重试。示例：

```text
读取来源 24 条
完成去重 18 条
生成候选变化 3 条
等待人工审核
```

不要展示模型隐藏推理、未经验证的中间猜测或完整 Prompt。

### 4. 动态 UI 受契约约束

结构化输出和流式数据可以驱动局部结果更新，但动态卡片、图表和操作必须来自允许的数据模型与组件白名单。AI 不得动态创建发布岗位所需的任意字段，也不得绕过审核流调用写入接口。

## Hiro2 页面落地

### 工作台

- 首屏显示待审核数量、最近岗位变化、证据质量和任务进度。
- AI 入口是上下文快捷动作，不放大型聊天面板。
- 点击指标进入对应列表或证据抽屉，而不是进入解释性对话。

### 新岗位发现

- 左侧是候选岗位列表，中间是结构化定义，右侧是证据和审核动作。
- AI 生成内容使用“候选”状态，名称、职责、技能和场景均可逐项修改。
- 每一项显示来源数量、置信度和支持/反证入口。

### 岗位更新

- 把新增、删除、修改作为视觉主线，基准版本和目标版本固定可见。
- “解释变化”只生成该行的解释和证据，不打开全屏聊天。
- 接受/拒绝/修改应在差异行内完成，发布在流程末端单独确认。

### 技能图谱

- 图谱负责发现关系，详情面板负责事实和证据。
- 默认只显示与当前岗位版本相关的节点；通过筛选或聚焦逐层展开。
- 节点动画只表达新增、删除、选中和加载，不做持续漂浮。

### 人岗诊断

- 先展示已具备、部分具备、缺失和关键短板，再展示解释。
- AI 可建议画像修正或学习顺序，但用户必须能逐项接受或修改。
- 结果、证据和学习动作保持同一上下文，避免跳转到独立聊天页。

## 动效规则

| 状态 | 推荐反馈 | 禁止做法 |
| --- | --- | --- |
| Loading | 保留最终布局，局部骨架和进度 | 整页闪烁、跳动布局 |
| Streaming | 增量更新结果和状态计数 | 连续打字式长文本占主区 |
| Selected | 细边框、背景色、轻微聚焦 | 大幅缩放、发光 |
| Accepted | 状态标签和局部确认 | 全屏庆祝动画 |
| Error | 错误位置、影响范围和重试 | 只显示通用 Toast |
| Empty | 下一步动作和必要上下文 | 大面积空白 |

所有动效必须支持 reduced motion；优先使用 opacity、transform 和局部颜色变化，不动画化页面布局。

## 迁移优先级

### P0：必须落地

- 上下文 AI 操作入口。
- 结构化候选结果和证据并置。
- AI 阶段状态、错误和重试。
- 差异行内审核和版本发布确认。
- 桌面/移动端首屏密度验收。

### P1：完成闭环后增强

- 命令菜单和快捷键。
- 可恢复的长任务进度。
- 图谱节点的渐进式展开。
- AI 结果卡片的局部实时更新。

### P2：谨慎评估

- 自由生成 UI。
- 全屏 Copilot。
- 复杂滚动叙事和 WebGL 背景。

## 验收清单

- [ ] 用户不打开聊天，也能完成新岗位、岗位更新和人岗诊断三条核心流程。
- [ ] AI 结果都有结构化字段、来源、置信度、时间窗口和审核动作。
- [ ] 页面首屏没有重复标题、无意义眉题或大面积无功能留白。
- [ ] 动效解释状态变化，且不影响证据阅读、键盘操作和 reduced motion。
- [ ] 参考案例只用于设计决策，正式业务事实仍来自 API 数据模型和证据库。
- [ ] 外部参考没有导致新增自定义基础组件或绕过 Ant Design / Ant Design X。
