# Hiro2 设计系统

## Overview

角色专属界面规范见 [`design-recruiting.md`](design-recruiting.md) 和 [`design-career.md`](design-career.md)。本文件只维护跨角色共享的视觉、证据表达和工作台规则。

**设计核心隐喻：“证据工作台”**

Hiro2 面向招聘负责人、技术岗位负责人和求职者。界面应像一张整理有序的证据工作台：安静的纸张表面、准确的结构线、紧凑的标签、可见的来源和清楚的状态变化。用户不需要阅读技术说明，就能理解当前岗位版本、发生了什么变化、变化依据是什么以及下一步可以做什么。

视觉源采用 `hiro/simulation-project/web` 的成熟界面语言：纸张色画布、细结构线、顶部导航、密集分析面板、蓝/黄/红/绿语义状态，以及与结果并置的证据区域。Hiro2 只继承这套视觉语言，不复制仿真项目的市场事件回放和 Agent 展示。

产品叙事固定为：

```text
市场信号 -> 证据 -> 岗位候选/岗位版本 -> 审核 -> 图谱 -> 候选人缺口 -> 学习路径
```

## 产品层次与共同信息结构

赛题要求的岗位发现、岗位更新、图谱和人岗诊断是基础能力；Hiro2 的差异不另设“亮点页”，而是让这些能力都围绕 `可信岗位版本` 运转。任何正式岗位结论都必须具有版本、时间、证据和审核状态；任何诊断或培养建议都必须回指该版本。

岗位详情、岗位差异、图谱节点详情和匹配报告使用同一组信息顺序：

```text
结论 -> 变化 -> 依据 -> 行动
```

| 信息 | 固定呈现 | 用户问题 |
| --- | --- | --- |
| 结论 | 当前状态、岗位版本、关键能力或关键短板 | 现在应相信什么？ |
| 变化 | 基准/目标版本、时间窗、新增/删除/修改 | 它和过去有什么不同？ |
| 依据 | 来源数、原文片段、时间、置信度、审核记录 | 为什么可信？ |
| 行动 | 审核、发布、开始诊断、生成训练任务 | 接下来做什么？ |

趋势与预测只以“待审核岗位影响建议”进入上述结构，不能在视觉上与已发布岗位事实并列。

首期业务导航包含工作台、新岗位发现、岗位更新、技能图谱、人岗诊断、评测中心。内部质量模式增加“数据资产”一级工作区；时间情报系统增加四个次级视图：信号流、信号簇、历史回测、预测复盘。证据抽屉、版本差异、审核操作和任务进度属于共享面板，不增加一级导航。

**核心特征：**

- 先展示证据，再展示解释。
- 使用紧凑工作台，不做营销型首屏。
- `job_version_id` 贯通岗位定义、图谱和匹配。
- 颜色表达状态，不承担装饰作用。
- 每个重要结论都展示来源、时间和审核状态。

## Frontend Component Stack

Hiro2 使用成熟组件库承载基础交互，不自行重写与组件库等价的按钮、表单、表格、抽屉、弹窗、标签、提示、空状态和加载状态。

```text
基础业务组件：Ant Design 6
AI 交互组件：Ant Design X 2.x
图谱：@xyflow/react
图标：Phosphor Icons
布局与局部样式：Tailwind，仅用于布局和 Token 辅助
```

- Ant Design 负责 Table、Form、Drawer、Modal、Tag、Tabs、Tooltip、Empty、Skeleton、Alert 等基础组件。
- Ant Design X 负责 Sources、Actions、ThoughtChain、FileCard、Sender 和结构化 AI 结果展示。
- `ThoughtChain` 只展示可审计的阶段、工具调用、数量、耗时和错误，不展示模型隐藏思维链。
- AI 生成的候选必须落入固定展示模型 和审核流程；不得通过动态组件绕过 API 契约或直接写入正式岗位版本。
- `design.md` 的颜色、圆角、间距和字体 Token 通过组件库主题配置映射，不代表重新实现一套平行组件。

## Interaction Model

Hiro2 是结构化 AI 工作台，不是聊天机器人。主交互是任务流程，AI 对话只用于表达意图、追问解释和临时操作。

```text
用户选择上下文
  -> AI 执行任务
  -> 显示可审计进度
  -> 生成结构化候选
  -> 查看证据和反证
  -> 接受 / 修改 / 拒绝
  -> 发布不可变岗位版本
```

- AI 入口必须嵌入当前任务，例如“解释变化”“查找反证”“补齐职责”，不默认占据首屏。
- AI 结果必须优先进入差异对比、证据列表、技能标签、匹配报告、审核队列或学习路径，不以长篇 Markdown 作为主要交付物。
- AI 候选、待审核项、已修改项、已接受项和已发布事实必须使用不同状态表达；AI 候选不得伪装成正式岗位事实。
- 任何 AI 结果都必须显示来源、时间窗口、置信度和下一步动作；对话不能成为获取核心结论的唯一入口。
- 复杂过程使用渐进式展开：首屏显示结论、状态、关键数值和证据入口，详细原文、运行日志和参数放入抽屉或详情。

## Colors

整体采用克制的纸张色系统，以黄色表示当前关注状态，以蓝、红、绿表示明确的业务语义。背景保持安静，让证据和变化成为视觉重点。

### Primary

- **信号蓝**（`#2457e6`）：链接、激活控件、正向能力变化和当前图谱边。
- **审核黄**（`#e4b810`）：当前选中、待审核、当前版本和需要关注的操作。

### Secondary

- **确认绿**（`#17824b`）：已确认证据、已发布状态和成功处理。
- **风险红**（`#dc3c34`）：删除能力、衰退信号、解析错误和缺失必备技能。

### Neutral

- **纸张**（`#f5f1e8`）：应用主画布。
- **浅纸**（`#faf8f2`）：次级画布和时间区域。
- **面板**（`#fffdf8`）：主要内容表面。
- **墨色**（`#20201d`）：主要文字和当前事实。
- **辅助灰**（`#77736b`）：说明文字和元数据。
- **结构线**（`#cfc8bb`）与**强调线**（`#aaa294`）：分隔线、表格线和图谱边框。

**语义颜色规则：**蓝、黄、红、绿必须表达可操作的状态，不得用于装饰或渐变。

## Typography

**展示字体：**`Arial Narrow`，回退到 `Inter` 和中文系统字体。
**正文字体：**`Inter`，回退到 `Noto Sans SC`、`PingFang SC`、`Microsoft YaHei`。
**标签/等宽字体：**`IBM Plex Mono`，回退到系统等宽字体。

正文保持中性、清晰；等宽字体用于 ID、版本、时间和置信度，让这些数据可以被检查；窄体展示字体只用于少量高优先级数字。

### 层级

- **Display**（400，30px，行高 1）：KPI 和最高优先级数字，不用于普通页面标题。
- **Page title**（650，24px，行高 1.25）：页面语义 H1 或重要对象标题。
- **Section title**（650，18px，行高 1.3）：面板标题、岗位名称和技能组标题。
- **Table body**（400/500，16px，行高 1.4）：数据表正文和高密度可比较信息。
- **Body**（400，14px，行高 1.5）：正文、表单、说明和证据内容，连续文本不超过 75 字符宽度。
- **Auxiliary / Label**（400/500，14px，行高 1.4）：来源、状态、时间、版本和辅助数值，通过颜色、字重和等宽字体区分层级，不再缩小字号。

分数、数量和时间使用 `font-variant-numeric: tabular-nums`。不使用整句大写。页面不得引入新的字体或 Token 之外的临时字号。

**可读性规则：**任何文字不得小于 14px；来源片段和辅助说明可以降低颜色或字重，但不得通过缩小字号制造层级。

## Information Density Rules

### 去冗余

- 每个路由必须保留一个语义 H1；H1 与当前导航完全相同时使用 `sr-only`，不在首屏重复显示。
- 对象页和结果页可以显示具体对象标题，例如候选人姓名或发布结果；页面内部区块从 H2 开始。
- 浏览器标题、导航标签和语义 H1 使用同一词表，浏览器标题统一为“页面名 | Hiro2”。
- 每个面板默认只保留一个 Section title。
- 禁止无业务价值的眉题、营销式副标题、重复说明和“标题 + 同义小字”组合。
- 不使用全局“当前阶段 / 下一步”横条重复导航和页面操作；状态与动作在对应内容区域就地呈现。
- 辅助说明只有在解释状态、来源、时间窗口、操作后果或下一步时才保留。
- 标题、标签、按钮和说明文字不得重复表达同一事实。

### 符号优先

- 搜索、筛选、关闭、展开、删除、下载、刷新、撤销等熟悉且单义的操作优先使用图标。
- 图标按钮必须提供 `aria-label` 和 Tooltip；有歧义的操作使用“图标 + 短动词”。
- 不使用 `>`、`...`、`x`、`+` 等字符模拟图标，统一使用 Phosphor Icons。
- 业务数量、版本、时间、置信度和评分必须保留文本，不能为了极简而替换成不可读符号。
- 状态不得只依赖颜色，应结合图标、短标签或明确的文本。

### 文字精简

- 操作文案使用动词优先和最短可理解表达，例如“筛选”“发布”“查看证据”。
- 删除“当前、已经、相关、这里、您可以”等不增加信息的词。
- 状态标签优先使用短词，例如“待审、已发布、缺失、低置信”。
- Empty 和 Error 只说明发生了什么以及下一步，不写背景介绍。
- 同一含义在页面内只使用一个术语；不要并列中英文表达同一含义。

### 留白控制

- 留白必须承担分组、层级、聚焦或可读性作用；无法说明用途的空区域视为布局问题。
- 只使用 spacing Token；页面和组件不得自行增加大段 padding 或 margin。
- 面板标题、内容和操作使用固定间距，不用空白模拟层级。
- 空状态必须有明确下一步，不得用大面积空白伪装简洁。
- 首屏优先保证上下文、主分析和证据入口可见；移动端按“上下文 -> 主分析 -> 证据”排序。

## Elevation

Hiro2 默认采用扁平层级。深度通过纸张色差、边框、间距和选中填充表达，不使用大范围阴影。面板使用 1px 边框和近似平面的表面，不把装饰性边框与宽软阴影叠加。

### 阴影规则

- **静止状态：**不使用阴影。
- **焦点控件：**使用 2px 蓝色焦点轮廓和小偏移。
- **抽屉/弹窗：**只有在需要与工作台分离时使用一层克制的背景遮罩和结构阴影。

桌面工作台使用固定顶部导航和三栏分析区。窄屏按“上下文 -> 主分析 -> 证据”的任务顺序堆叠。图谱和版本对比区域可以内部滚动，页面本身不能产生意外横向溢出。

## Components

### 按钮

- **形状：**4px 圆角，标准高度 34px；需要解释的操作使用图标加“动词 + 对象”文本。
- **主按钮：**墨色背景、面板色文字，用于“发布岗位版本”“开始诊断”等动作。
- **关注按钮：**审核黄只用于当前主要关注动作，例如“审核候选岗位”。
- **次按钮：**透明或面板背景加结构线。
- **Hover/Focus：**改变背景或边框；焦点使用可见的 2px 蓝色轮廓，不使用抬升动画。

### 状态标签

- 使用紧凑标签表示 `PUBLISHED`、`REVIEWING`、`LOW CONFIDENCE`、`SYNTHETIC` 和来源类型。
- 选中/待审核用黄，确认用绿，风险/缺失用红，中性元数据用纸张色和结构线。
- 标签必须命名状态，不用来宣传功能。

### 面板与表格

- **圆角：**4px，不使用卡片套卡片。
- **表面：**面板置于纸张画布上，以 1px 结构线分开。
- **内边距：**紧凑行 16px，主要面板 20px，编辑器 24px。
- 表格使用稳定列宽，交互行最小高度 48px，选中行清晰可辨。
- 点击表格行打开详情或证据状态，不把唯一操作藏在难以发现的小图标里。

### 图谱与版本差异

- 岗位节点：墨色或深色面板。
- 必备技能：蓝色；加分技能：中性色；新增技能：蓝/黄；删除技能：红色；待审核技能：虚线边框。
- 边表示关系，不做装饰。只有能够帮助判断时才显示权重或变化标签。
- 选中节点后打开指标条和证据抽屉。
- 岗位差异 固定使用“新增 / 删除 / 修改”三列，并始终显示基准版本和目标版本。

### 证据抽屉

每个结论都可以打开证据抽屉，包含来源、发布时间、采集时间、原文片段、质量分、支持的结论和审核动作。证据抽屉是解释与来源之间的固定桥梁。

### 导航

三个工作区按角色切换，角色专属导航见 [`design-recruiting.md`](design-recruiting.md)、[`design-career.md`](design-career.md) 和 [`design-data.md`](design-data.md)：

```text
招聘：工作台 / 我的岗位 / 岗位发现 / 能力全景 / 候选诊断
求职：目标岗位 / 我的画像 / 人岗诊断 / 学习路径 / 简历工作台
数据：总览 / 来源 / 流水线 / 审核任务 / 评测与质量 / 时间情报
```

当前路由通过文字字重和细下划线表达。导航必须改变 URL 和内容，不能只改变激活样式。

### Loading、Empty、Error

- Loading 保留最终布局，用安静的骨架行替换数据。
- Empty 必须说明下一步，例如“选择一个岗位版本开始对比”。
- Error 说明哪里失败、已有数据是否仍可使用以及重试动作。
- 待审核是业务状态，不是错误；显示证据数量和审核动作。

### 协作评测

- “我的任务”优先展示任务类型、优先级、数据来源、运行版本和当前状态。
- 审核工作区固定采用三栏：原文与证据、系统结果、人工决策；审核者不需要下载或切换外部文件。
- 提交前显示修改摘要，提交后显示任务状态和是否需要双人复核。
- 质量看板展示完成率、复核率、错误分布和新旧运行对比，不只展示一个总准确率。

## Do's and Don'ts

### Do:

- **Do** 在结论附近显示 `job_version_id`、证据、时间和审核状态。
- **Do** 使用纸张、墨色、结构线作为基础，只用语义色表达状态。
- **Do** 让主分析位于中间，证据在一次交互内可达。
- **Do** 使用统一字号和等宽数字展示指标。
- **Do** 为每个核心页面准备默认、加载、空、错误和已审核状态。
- **Do** 让岗位更新流程的视觉重点落在前后版本变化上。
- **Do** 让 AI 结果直接落入结构化业务对象和审核动作。
- **Do** 使用成熟组件库的原生能力，并通过主题 Token 定制 Hiro2 视觉。

### Don't:

- **Don't** 把 Hiro2 做成营销落地页或普通 SaaS 大屏。
- **Don't** 把仿真项目的市场事件回放直接复制到岗位分析页面。
- **Don't** 使用装饰性渐变、玻璃拟态、超大圆角卡片或嵌套卡片。
- **Don't** 使用超过 1px 的彩色侧边条作为主要状态指示。
- **Don't** 在用户需要来源证据时展示冗长的 LLM 对话日志。
- **Don't** 展示没有单位、时间窗口或证据链接的大数字。
- **Don't** 用总匹配分掩盖必备技能缺失。
- **Don't** 在页面组件中添加新字体、临时字号或一次性颜色。
- **Don't** 让合成数据看起来与正式市场证据完全相同。
- **Don't** 把对话框、长篇 Markdown 或模型过程文本作为核心页面。
- **Don't** 把 AI 候选直接显示成已发布岗位事实。
- **Don't** 为 Ant Design 已提供的基础组件新增平行自定义实现。
- **Don't** 在标题上方批量添加无意义的小字、眉题或解释性副标题。
- **Don't** 用大面积空白、重复面板或冗余文案制造“高级感”。
