# 评测与交付

## 官方硬指标

| 指标 | 要求 | 必须保存 |
| --- | --- | --- |
| JD 解析准确率 | >=90% | 标注集、Precision/Recall/F1、错误案例 |
| 简历技能提取准确率 | >=90% | 文件类型、标注集、Precision/Recall/F1、错误案例 |
| 人岗匹配准确率 | >=90% | 匹配等级、Accuracy/Macro F1、混淆矩阵 |
| JD 与测试用例 | >=100 条 | 输入、预期、实际、人工判定 |
| 单元测试覆盖率 | >=60% | 命令、报告、核心模块覆盖 |

## 亮点验证指标

除官方准确率外，还必须验证“多源、可信、动态”是否真正带来可用价值。以下指标不替代官方硬指标，但必须在答辩案例中展示计算方法和错误样本：

| 指标 | 含义 | 最小验收 |
| --- | --- | --- |
| 证据覆盖率 | 正式岗位字段、岗位变化和匹配关键结论中可回链 `evidence_id` 的比例 | 关键结论 100% 可回链 |
| 审核一致性 | 双人独立审核在同一 case 上的初始一致程度 | 记录一致率、分歧和复核结论，不隐藏分歧 |
| 岗位变化命中率 | 发布/建议的新增、删除、修改是否被后续 JD 或专家判断支持 | 每个历史切片保存命中与错判样本 |
| 预测提前量 | 趋势建议早于后验 JD/事实出现的时间 | 按 30/60/90 天窗口统计，不只报单个最佳案例 |
| 行动可达率 | 用户从结论到证据、审核或下一步任务是否可完成 | 核心任务测试记录完成率与卡点 |

## 测试数据规则

- 至少 100 条真实、可追溯 JD 作为基础测试集合。
- 每条测试用例必须有输入、标准答案、实际输出和人工判定。
- 简历测试数据使用授权或严格脱敏样本。
- 调优数据与最终测试数据隔离。
- 合成数据必须标记 `synthetic=true`，不得计入准确率。
- UI 展示指标只能来自 `evaluation_runs`，禁止手工填写。

## 评测对象

```text
evaluation_cases
  -> evaluation_annotations
  -> evaluation_runs
  -> evaluation_predictions
  -> evaluation_metrics
```

每次运行记录：模型版本、提示词版本、算法版本、数据集版本和运行时间。

## 历史回测

历史回测验证系统在不知道未来数据时，能否提前发现技能和岗位变化。每个回测切片遵守：

```text
as_of_date = T
输入：available_at <= T 的数据
预测：T + 30/60/90 天
验证：读取 T 之后的日报、JD 和其他后验数据
```

建议使用滚动时间切片，并保留一段从未参与调优的最终测试窗口：

```text
调优窗口：2025-01 ~ 2025-09
验证窗口：2025-10 ~ 2025-12
封存测试窗口：2026-01 ~ 2026-03
```

历史补录数据标记为 `backfill`。如果没有当时的抓取日志，只能称为“基于发布时间的历史回放”，不能宣称是在线实时预测复现。

### 回测指标

| 指标 | 含义 |
| --- | --- |
| 趋势方向准确率 | 升温、稳定、衰退方向是否正确 |
| 新技能发现 Precision/Recall | 提前发现的技能是否后来真实出现 |
| 预测提前量 | 预测信号早于 JD/后验事实多少天 |
| 置信度校准 | 高置信预测是否有更高实际准确率 |
| 岗位变更命中率 | 预测的岗位新增或权重变化是否被后续数据支持 |

每次回测必须保存错误类型：时间泄漏、技能归一化错误、热点误判、来源偏置、岗位映射错误、预测滞后和无证据幻觉。

## 标注工作流

冻结样本的标注闭环为：

```text
evalset.py freeze（分层抽样，manifest 哈希锁定）
  -> prelabel.py（AI 预标注：建议判定 + 置信度 + 理由，写入 prelabels.jsonl）
  -> /tasks 页人工确认（采纳建议或修改后提交，写入 annotations.jsonl）
  -> evalset.py score（标注回流后确定性计算，产出 metrics.json）
```

规则：

- AI 预标注只是候选，不计入指标；只有写入 `annotations.jsonl` 的判定才参与 score。
- 标注记录 append-only，带 `reviewer_id` 与 `dataset_version`；批量 AI 采纳必须透明标记（如 `ai-prelabel-batch`），与人工判定可区分。
- 跨版本对比必须锚定固定样本的 `jd_id`（`evalcmp.py`），因为 freeze 按方法分层抽样，系统输出变化会导致样本漂移，直接比两版分数口径不成立。

### 抽检智能体（evalaudit）

人工抽检前先跑 `scripts/evalaudit.py`：抽检智能体对 AI 预标注做独立二次判定（查证工具只读：岗位目录/岗位详情/JD 详情/事件详情），每 case 独立 agent run 留痕（`agent-steps.jsonl` + token 预算硬闸门），产出分歧清单（`audit-summary.json`）——agent 判定与预标注不一致的 case 即人工优先复核对象。抽检策略：非 ACCEPT 全复核 + ACCEPT 抽 10%，固定 seed 可复现。agent 判定不写入 annotations、不参与 score；正式指标仍以人工确认为准。

### 评测-修正飞轮（evalloop）

`scripts/evalloop.py` 把"发现错误 -> 修正规则 -> 重评"连成轮次：非 ACCEPT case 聚类（叠加抽检分歧视角）-> 分析智能体归纳错误模式、产出规则补丁建议（`patch-suggestions.json`，target 指向 rolemap.py 具体常量）-> 人工审核应用 -> rolemap 规则层重跑（零 LLM 成本）-> `evalcmp.py` 固定样本对比。建议不自动应用；负改进由对比如实呈现并可回滚。这层循环是发榜方"效果测评与闭环优化"方向的直接落地。

### gold 锚定与口径（2026-09-01）

岗位映射的判定链：AI 预标注（批量建议）→ 抽检智能体独立复核（分歧清单）→ ai-cross-review 逐条职责证据裁决 → **锚定**（`corrected_payload` 落定标准答案，含显式 None=目录外）。锚定后：

- **score 口径**：标准答案（corrected_payload）vs CSV 系统输出列（实际输出，随 repair 刷新）直接比较；ACCEPT 无锚定的沿用字母语义。
- **evalcmp 口径**：锚定 jd_id + repaired 当前输出，修复/回归计数。已知边界：CSV 刷新后 ACCEPT 无锚定 case 的期望随输出走（检测力弱化），主数字以锚定对齐 + score 双口径呈现。
- **repair 治理链**：锚定 > 继承 semantic（缓存式幂等，重跑不漂移）> 规则 + 语义重判；`--semantic-force` 才重判。
- 方案选型（shootout，10 条难例 → 99 条全量两步验证）：任务分解两段式 + 判例 few-shot（S4）胜出，已回填 role-semmap v3。

### 词表新词闭环（aliasprobe）

词表不再是静态人工先验：`scripts/aliasprobe.py` 从数据流发现词典外语言并生成词表提议。信源一：unmatched JD 标题关键词聚类（复用 emergscan n-gram，>=5 次成簇）；信源二：日报 skill_mentions 月度突增检测（近 3 月/历史月均 >=3 倍，先导预警——时间传导轴证明日报先导 JD 5~7 年）。提议 agent 逐簇查证样本 JD 职责与岗位职责，产出三类判定：add_alias（词典缺口）/ new_position_signal（46 岗对不上，转新岗位流）/ reject（噪声词）。提议经人工审核后进 TITLE_ALIASES，repair 重跑 + evalcmp 验证。首次运行（2026-08-31）：410 候选 -> 前 15 查证 -> 12 新岗信号 + 2 弃 + 1 词典缺口，FDE 簇与涌现扫描结论互相印证。

## 未来预测

未来预测使用同一个 `ForecastEngine`，把 `as_of_date` 设置为当前时间，并为每项结果保存 `forecast_valid_until`。预测结果只进入当前趋势和岗位变化建议，不直接覆盖岗位图谱。

## 错误分类

至少统计：技能同义词未归一化、技能粒度错误、必备/加分判断错误、年限或熟练度错误、项目场景误判、无证据技能幻觉、重复 JD 未过滤、时间窗归属错误。

## 前端协作评测

评估、分析和领域审核同学直接在系统前端完成任务，不通过数据包或聊天记录回传结论。

| 任务类型 | 审核内容 | 系统产物 |
| --- | --- | --- |
| JD/技能审核 | 职责、必备/加分、岗位、等级、技能映射 | `EvaluationAnnotation` |
| 证据审核 | 原文是否支持结论、来源质量、冲突 | Evidence 质量和复核记录 |
| 岗位审核 | 新岗位定义、岗位差异、版本发布 | `ReviewAction` |
| 预测复盘 | 命中、错判、提前量和错误类型 | `PredictionReview` |
| 匹配审核 | 画像、关键短板、学习路径 | Match 评测标注 |
| 体验验收 | 三条流程是否可理解、完成和信任 | UX 任务结果和缺陷记录 |

每个任务必须显示原文、系统结果、证据、时间和运行版本。审核者可接受、修改、拒绝或标记无法判断。至少 20% case 双人独立审核，分歧进入复核队列。

### 最小协作规模

```text
JD 解析与技能标注：100 条
技能归一化：100-150 个提及
日报事件与阶段判断：50-80 个事件
历史预测复盘：20-30 条预测
人岗匹配：30-50 个候选人-岗位对
体验测试：5 人，每人完成 3 条核心任务
```

质量看板必须展示任务完成率、复核率、指标、错误分布和新旧 `run_id` 对比。

## 测试层级

| 层级 | 内容 | 工具 |

## 交付包

新岗位和既有岗位各一份案例包，包含原始数据源、清洗/抽取结果、输入示例、预期输出、实际输出、图谱版本、审核记录、评测用例和复现命令。

软件包包含源码、锁定依赖、Dockerfile/Compose、`.env.example`、schema 初始化、案例导入、`/health` 检查、单测和 coverage 报告。

## 答辩证据

```text
真实数据 -> 可信处理 -> 岗位变化 -> 图谱版本
-> 简历匹配 -> 准确率验证 -> 可部署演示
```

10 分钟只演示：数据质量门、新岗位定义与人工发布、既有岗位新增/删除/修改、技能点图谱、简历修正和差距、测试指标和错误案例。
