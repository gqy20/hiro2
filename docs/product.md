# 产品定义

## 结论

Hiro2 面向新一代信息技术企业的招聘负责人、技术岗位负责人和新兴领域青年，基于多源数据构建可追溯、可动态更新的岗位能力标准，完成岗位定义、岗位更新、人岗差距诊断和能力提升反馈。

## 产品取向

产品有两层目标，缺一不可：

```text
赛题基本盘：新岗位、岗位更新、图谱、简历解析和人岗诊断完整可用
贯穿亮点：每个结论由多源证据支持，经人工审核成为可回溯的岗位版本，并驱动下游行动
```

`可信岗位版本` 是全产品的核心产物，不是一份静态 JD：它包含能力要求、适用时间、来源证据、审核记录和版本状态。图谱、JD 模板、人岗诊断和培养任务只能消费已发布版本，不能各自维护另一套岗位定义。

## 用户与任务

| 用户 | 首要任务 | 交付结果 |
| --- | --- | --- |
| 招聘/技术负责人 | 定义岗位、更新能力、诊断候选人 | 岗位版本、证据、匹配报告 |
| 求职者/学生 | 了解目标岗位和个人缺口 | 可编辑画像、差距、学习路径 |
| 内部审核/评测角色 | 判断系统结论是否可靠 | 接受、修改、拒绝、复核 |
| 高校就业老师 | 观察市场需求变化 | 岗位趋势和群体缺口（P1） |
| 企业人才培养负责人 | 将岗位标准转化为培养任务 | 团队缺口、训练任务和能力证明（P1） |

完整的用户触发、决策路径、异常处理和体验验收见 [`user-scenarios.md`](user-scenarios.md)。

## 首期范围

覆盖 AI、大数据、智能系统、物联网四个方向；首期优先完成 AI 和大数据案例。

主案例：

1. **AI Agent 工程师候选**：新岗位发现、与既有岗位对比和人工定义。
2. **AI 应用工程师**：两个时间窗的能力新增、删除、修改。
3. **候选人 A**：手工技能或 PDF/DOCX 简历到人岗诊断。

## P0 闭环

```text
来源登记 -> JD/简历解析 -> 技能标准化 -> 证据质量
-> 新岗位发现 / 既有岗位 diff -> 人工审核 -> 岗位版本
-> 多维匹配 -> 差距分析 -> 学习路径
```

日报/RSS、历史回测和预测负责为岗位更新提供可信性支撑；它们不替代新岗位、岗位更新、图谱和诊断四项用户主路径。P1 才考虑 RAG、多 Agent 和职业沙盒等扩展体验。

## AI 应用边界与亮点

AI 不是独立的聊天功能，也不替代人的招聘判断。它只在有固定输入、结构化输出和审核出口的环节发挥作用：

| AI 角色 | 输入 | 结构化产物 | 不可跨越的边界 |
| --- | --- | --- | --- |
| 结构化抽取 | JD、简历、日报 | 技能、职责、事件和原文片段候选 | 不把自由文本当作业务事实 |
| 多源归因 | 多来源候选和证据 | 去重、冲突、变化、置信度和证据关联 | 不凭单一热点认定岗位变化 |
| 时间推演 | 截止日期前的趋势特征 | `JobImpactSuggestion` 和可回测预测 | 不直接修改岗位版本 |
| 行动解释 | 已发布岗位版本和候选人画像 | 差距、优先级、训练任务和解释 | 不输出录用/淘汰决定 |

亮点不在于“使用了 Agent”，而在于 AI 每次输出都能进入下列闭环：

```text
结构化候选 -> 证据与反证 -> 人工接受/修改/拒绝
-> 已发布岗位版本 -> 图谱、诊断、培养输出 -> 评测与复盘
```

## AI 应用工程能力链

岗位标准以能力链组织，具体工具只是可变化的技能点：

```text
需求与场景理解
-> 数据与知识处理
-> 智能体与工作流构建
-> 工具与系统集成
-> 效果评测与迭代
-> 部署、运营与治理
```

例如 MCP、RAG、LangGraph、向量数据库属于对应能力域下的技能点，不能用短期工具热度替代岗位能力本身。

## 功能验收

### 新岗位发现

- 从标题变体、技能共现、跨公司和跨来源信号生成候选。
- 定义卡包含：名称、核心职责、必备技能、加分技能、典型行业场景。
- 支持人工编辑、审核、发布、版本 diff 和回滚。

### 既有岗位更新

- 用户选择岗位、基准窗口和观察窗口。
- 输出新增、删除、修改三类能力项。
- 每项展示变化说明、权重、数据源和审核状态。
- 发布后形成不可变的新岗位版本。

### 全景图谱

- 岗位可展开到必备/加分技能和技能点。
- 支持技术栈、级别、能力类型、时间/版本视图。
- 任意结论可打开来源、原文片段、时间和审核记录。

### 人岗诊断

- 支持手工技能、熟练度、年限、项目证据、证书和行业经验输入。
- 支持 PDF、DOCX 简历上传和解析结果人工修正。
- 输出已具备、部分具备、缺失、匹配总览、关键短板和学习路径。
- 修改候选人画像后可重新计算。
- 输出是发展建议，不是自动淘汰、自动录用或唯一招聘结论。

### 岗位标准下游输出

每个已发布岗位版本可生成：

- 面向企业的招聘 JD 能力模板；
- 面向诊断的候选人能力要求；
- 面向培养的训练任务和能力阶梯；
- 面向青年发展的“学练赛证”能力提升路径。

“学练赛证”表示：学习知识点、完成项目练习、参与实践评测、沉淀能力证明；首期不接入具体课程或证书平台。

### 协作评测工作台

- 系统运行后自动生成数据审核、预测复盘和岗位审核任务。
- 同学在前端直接查看原文、系统结果、证据和置信度，提交接受、修改、拒绝或无法判断。
- 评测中心展示任务完成率、指标、错误类型和新旧运行对比。
- 前端协作反馈是正式数据资产，不依赖线下分发数据包。

## 评分策略

| 评分项 | 重点证据 |
| --- | --- |
| 完整性 30 | 多源数据到匹配的同一条闭环；新岗位和既有岗位案例 |
| 创新性 25 | 去重、时效、交叉验证、幻觉拦截的前后对比 |
| 用户体验 15 | 三条流程连续完成，图谱和缺口清晰 |
| 实用价值 30 | >=100 条 JD 及测试用例、三项准确率 >=90%、部署和迁移证据 |

## 不做

- 自动淘汰或自动录用。
- 无证据的模型事实。
- 只展示总分、不展示技能依据。
- P0 完成前扩张到泛行业平台。
