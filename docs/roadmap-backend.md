# 后端 Roadmap

> 范围：数据、领域模块、API、异步任务、LLM 适配、图谱投影、评测和部署。
> 依赖：[`architecture.md`](architecture.md)、[`contracts.md`](contracts.md)、[`roadmap-data.md`](roadmap-data.md)。
> 当前阶段：T1。状态只使用：未开始、进行中、阻塞、待验收、完成。

## 共享阶段

| 阶段 | 目标 | 后端退出条件 |
| --- | --- | --- |
| T1 数据与证据 | 建立事实主库和证据链 | D1-D5 数据退出条件满足，可导入完整 JD 并回到原文 |
| T2 岗位演化 | 完成候选发现、Diff、审核和版本 | D3-D7 数据退出条件满足，两个主案例可发布岗位版本 |
| T3 图谱与诊断 | 完成图谱、简历解析和匹配 | 返回稳定的 `MatchReport` |
| T4 评测与交付 | 完成指标、部署和稳定性 | 评测可重跑，Compose 可启动 |

## 后端完成定义

- [ ] API DTO 与 `contracts.md` 一致，并通过 Pydantic 校验。
- [ ] LLM 不直接写正式岗位版本或 Neo4j。
- [ ] 所有正式结论都有 `evidence_ids`。
- [ ] PostgreSQL 是事实主库，Neo4j 和向量索引可重建。
- [ ] 发布版本不可变，审核动作可审计。
- [ ] 评测脚本不依赖前端，指标可在命令行重跑。
- [ ] 历史回测和未来预测共用 `ForecastEngine`，仅模式和数据截止时间不同。
- [ ] 预测只能生成岗位变化建议，不能绕过审核发布岗位版本。
- [ ] Docker Compose、迁移、种子和健康检查可用。
- [ ] 时间情报系统不依赖旧 hiro 或 rss2cubox 数据库，可独立运行。
- [ ] 审核和评测反馈以 `ReviewTask`、`EvaluationAnnotation` 和 `PredictionReview` 保存，不依赖线下数据包。
- [ ] 任何正式岗位或匹配结论都可输出“结论、变化、依据、行动”所需的稳定 View Model，不只返回分数或模型文本。
