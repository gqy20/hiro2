# 前端 Roadmap

> 范围：页面、交互、设计系统、Mock 数据、API 接入和端到端验收。
> 依赖：[`design.md`](design.md)、[`contracts.md`](contracts.md)。
> 当前阶段：T1。状态只使用：未开始、进行中、阻塞、待验收、完成。

## 共享阶段

| 阶段 | 目标 | 前端退出条件 |
| --- | --- | --- |
| T1 数据与证据 | 建立应用壳层和数据展示基础 | 设计 Token、导航、证据抽屉和 Mock API 可用 |
| T2 岗位演化 | 完成新岗位和既有岗位页面 | 候选审核、岗位 Diff、版本发布流程可演示 |
| T3 图谱与诊断 | 完成人岗诊断闭环 | 图谱、简历修正、匹配报告和学习路径可用 |
| T4 评测与交付 | 完成稳定性和答辩验收 | Playwright、响应式、错误状态和生产构建通过 |

## 前端完成定义

- [ ] 页面使用 `design.md` 的 Token，不自行添加颜色和字号。
- [ ] 基础交互使用 Ant Design 6，AI 交互使用 Ant Design X 2.x，不重复实现等价基础组件。
- [ ] 主路径是结构化任务流程；对话只是上下文辅助入口，不承载核心结论。
- [ ] AI 输出进入固定 View Model、证据和审核流，不直接伪装成正式岗位事实。
- [ ] 页面没有重复标题、无意义眉题、冗余说明或无法解释的垃圾留白。
- [ ] 熟悉操作使用图标，图标按钮具备 Tooltip 和 `aria-label`；业务数据保留文本。
- [ ] AI 过程只展示可审计状态、工具和结果，不展示隐藏思维链。
- [ ] 页面只消费 `contracts.md` 定义的 View Model。
- [ ] 所有异步任务有进度、失败和重试状态。
- [ ] 所有结论可以打开证据抽屉。
- [ ] 岗位结论、图谱节点和匹配报告均按“结论 -> 变化 -> 依据 -> 行动”呈现；不得只显示模型总分或长篇 AI 文本。
- [ ] Mock 与真实 API 使用同一 TypeScript 类型。
- [ ] 三条核心流程通过 Playwright。
- [ ] 历史回测页和当前趋势页不直接修改岗位版本，只展示预测和更新建议。
- [ ] 时间情报页面使用自己的任务语义，不复制旧仿真项目的事件回放界面。
- [ ] 审核者无需下载数据包，即可在前端完成标注、复盘和岗位审核。
