# Hiro2 作品设计实现方案

> 参赛题目：XH-202621《多源异构数据驱动岗位和能力图谱构建与动态演化分析研究》（发榜单位：科大讯飞股份有限公司）
>
> 在线系统：**https://hiro2.gqy20.top**（求职区/招聘区/数据审核区三工作区）　·　后端 API：**https://api.hiro2.gqy20.top**　·　源码仓库：**https://github.com/gqy20/hiro2**

## 1. 作品概述

### 1.1 一句话定位

Hiro2 是一套面向新一代信息技术领域的**可信岗位能力标准系统**：从多源异构数据中发现新兴岗位、追踪既有岗位的能力演化，经人工审核后形成带版本号、带证据链的岗位能力标准，并基于该标准完成技能点级全景图谱、人岗差距诊断与"学练赛证"学习路径。

核心产物不是一份静态 JD，而是**可信岗位版本**：每个结论有版本号、有证据、有审核记录；AI 的预测只作为建议，经人工审核后才能成为正式标准。

### 1.2 对赛题三大核心难题的回应

| 赛题难题 | 本作品的回应 | 详见 |
| --- | --- | --- |
| 难题一：从海量多源数据中发现并定义新兴岗位，更新既有岗位能力，构建可动态更新的图谱 | 涌现岗位自动扫描（四重判据）+ 双时间窗对比 + 人工审核发布不可变版本，一套岗位定义贯通图谱与匹配 | §2 |
| 难题二：招聘数据的"时滞""噪声""抄袭"与 AI 内容"幻觉"防控 | 五道数据质量门 + 双数据流交叉验证 + 时间封闭闸门 + 证据强制回链 | §2.2 §3.2 |
| 难题三：高精度简历解析与细粒度人岗差距分析 | PDF/Word 简历解析 → 候选人画像 → 对照已发布岗位版本多维匹配 → 分层差距 → 学练赛证路径 | §2.4 |

## 2. 系统设计与全流程闭环

官方要求："研发并完成多源数据采集→新岗位发现与定义和既有岗位能力更新→能力图谱动态→简历解析→精准匹配与差距分析全流程闭环系统。"

本作品该链路**全部贯通，且四个功能共享同一个事实中心**——这是与其他方案最本质的区别：岗位发现、岗位更新、图谱、简历匹配不是四套独立功能，而是消费同一个"已发布岗位版本"：

```text
多源数据与时间信号 → 证据/建议 → 人工审核 → 已发布岗位版本（唯一事实源）
                                              ├→ 全景图谱
                                              ├→ JD 模板
                                              ├→ 人岗诊断与差距分析
                                              └→ 学练赛证学习路径
```

### 2.1 四项功能要求逐条对照

| 官方要求 | 实现（均已上线并有端到端测试覆盖） |
| --- | --- |
| ① 新岗位发现与定义：岗位名称、核心职责、必备技能、加分技能、典型行业应用场景，支持人工优化 | 自动涌现扫描产出候选（含上述全部要素字段），人工审核后发布为岗位版本；验证案例见 §2.3 |
| ② 既有岗位能力动态更新（新增/删除/修改 + 更新说明及数据源） | 双时间窗对比引擎逐条输出变化 + 证据 + 时间窗；人工审核后发布新版本（已发布 17 个版本） |
| ③ 全景图谱：技能点粒度，按技术栈和级别切换 | 岗位→能力→技能点三层图谱，支持**技术栈 / 级别 / 能力类型三个维度筛选切换**，ReactFlow 交互式渲染 |
| ④ 人岗匹配：简历解析（PDF/Word）、多维匹配、改进建议与学习路径 | PDF/DOCX 上传 → 技能提取 → 对照已发布岗位版本 → 必备/加分分层差距 → 学练赛证四段路径 |

### 2.2 闭环链路与版本机制

```text
来源登记（17 类来源，每类逐项登记数据许可与时间范围：
          招聘平台 BOSS 直聘/51job ｜ 企业官网 字节/阿里/腾讯 ｜ 前沿 AI 公司
          OpenAI/xAI/月之暗面等 10 家 ｜ 技术日报"橘鸦 AI 早报"微信公众号（697 篇）｜
          24 个技术 RSS 直连源 ｜ 人社部国家职业标准 ｜ 教育部 1+X 证书 ｜
          讯飞 AI 开发者大赛/阿里天池/DataFountain 赛事目录 ｜ 美国职位数据库 O*NET 等）
  ↓  五道质量门（结构 → 去重 → 岗位归一 → 技能归一 → 证据质量）
  ↓  新岗位候选（自动涌现扫描）+ 既有岗位双时间窗对比
  ↓  人工审核（接受 / 修改 / 拒绝，全程留痕）
  ↓  发布不可变岗位版本（修改 = 发布新版本，历史版本永久可查）
  ↓
技能图谱投影、人岗匹配、差距分析、学习路径
```

**版本机制**：已发布的岗位版本内容固定，需要修改时发布新版本；下游功能（图谱、模板、诊断、学习路径）都引用明确的版本号，历史版本始终可查。

### 2.3 两个主案例（对应官方要求的"1 个新岗位 + 1 个既有岗位"测试数据）

**案例一 · 新岗位：AI Agent 工程师**

系统从技术日报与开源生态数据中发现"AI Agent"岗位的招聘需求在快速上升 → 自动扫描 28 个平台、10,384 条 JD，检出该岗位 13 个月内从个位数增长到数百条 → 生成岗位定义草案（岗位名称 / 核心职责 / 必备技能 / 加分技能 / 典型行业应用场景，每个字段附 JD 原文证据）→ 人工审核确认 → 发布 v1 → 自动生成技能图谱与 JD 模板 → 求职者诊断与学习路径即刻可用。

**案例二 · 既有岗位：AI 应用工程师（能力动态更新）**

系统将 2022-2024 与 2024-2026 两个时间窗的 JD 池自动对比，产出 13 项能力变化（新增 6 项 / 修改 4 项 / 删除 3 项），每项变化附证据原文与置信度 → 人工逐条审核（接受 / 拒绝 / 待确认）→ 发布 v3 版本 → 后续匹配自动消费新版本。能力变化中包括"Agent 编排"从无到有、"传统前端框架"从必备降为加分——这正是赛题说的"识别其能力要求的变化"。

两个案例的完整材料（原始数据、输入输出示例、审核记录、复现命令）见附录 A。

### 2.4 人岗诊断与学习路径

用户上传 PDF/DOCX 简历或手工录入技能（164 份真实简历档案已入库）；系统解析技能要素（含必备/加分分层、经验年限），对照**已发布**岗位版本输出多维匹配报告（必备技能满足度、加分技能覆盖、置信度），按优先级给出差距清单；"学练赛证"四段学习路径将每个缺口技能对应到真实数据：**学习**（人社部国家职业标准知识点）、**练习**（实训项目）、**竞赛**（讯飞 AI 开发者大赛等 1,269 场真实赛事）、**证书**（人社部 1+X、华为、阿里云、讯飞认证等 916 张真实证书）。

## 3. 核心技术方案与创新

官方要求："创新性应用大模型、知识图谱等技术……核心技术方案（如多源异构数据清洗与交叉验证机制解决数据时滞与噪音、基于'幻觉'防控的图谱构建）具备突破性与可行性。"本作品共有五大创新点，每个都有量化验证。

### 创新点 1：五道质量门 + 双数据流交叉验证——系统性解决数据的"时滞、噪声、抄袭"

赛题点名"JD 带滞后性、存在严重抄袭和通胀"。本作品的解法是**把质量把控制度化为五道门，而不是靠人工把关**：

| 质量门 | 拦截什么 | 机制 |
| --- | --- | --- |
| 1 · 结构修复 | 编码错误、字段缺失、日期格式混乱 | 自动修复 + 可重建，原始数据只读保留 |
| 2 · 身份与重复 | JD 抄袭、转载、多平台重复发布 | 内容指纹聚类识别重复簇，同簇只留一条主记录 |
| 3 · 岗位与等级归一 | 同一岗位多平台口径不一（如"算法工程师"/"ML Engineer"） | 46 个标准岗位目录 + 别名词表 + L4/L3/L2/L1 等级推断，全部记录推断依据 |
| 4 · 技能归一化 | 同一技能多种写法（"LLM/大模型/大语言模型"） | 词典归一 + 语义归一，归一命中可审计 |
| 5 · 证据质量 | 无来源、不可回链的结论 | 每条结论强制挂证据 `evidence_id`，无证据内容在质量门被拦截 |

**交叉验证**：技术日报（先导信号，反应行业注意力）与企业 JD（需求验证，反应企业实际动作）是两条**独立采集、独立清洗**的数据流，任何"岗位能力变化"结论都需要两路信号支持——防止单源热点误判。

**量化效果——把"时滞"从定性变成可测量的独家数据资产**：我们采集了四层历史数据，恰好对应技术从萌芽到被企业采用的完整路径：学术论文（arXiv，14,830 篇，技术最先出现）→ 开源生态（PyPI/npm 下载量，127 个月时间序列，工程师开始采用）→ 技术日报（微信公众号"橘鸦 AI 早报"，697 篇解析出 10,645 个事件，行业关注）→ 招聘 JD（10,384 条，28 个平台，企业实际招人）。据此测得：

- "大模型应用"从论文爆发传导到 JD 出现：**约 70 个月**
- "Prompt 工程"是反向案例：**市场实践先于学术爆发 26 个月**（说明单一信号源会误判方向）
- 中美对照：美国 O*NET 2005-2025 五版本 + 中国职业大典 2015→2022→动态新增 76 职业

**这条传导链的独家性**：需要同时覆盖论文、开源生态、技术媒体、招聘市场四层 9 年时间序列的多源数据，市场上任何只做招聘数据的产品都不具备。

### 创新点 2：系统性幻觉防控——不是"请 LLM 别编"，是"让 LLM 编不了"

我们的防幻觉不是提示词约束，而是**四道结构性防线**：

| 防线 | 机制 | 效果 |
| --- | --- | --- |
| **证据强制回链** | 每条岗位/技能/匹配结论必须挂 `evidence_id`；无证据内容在质量门被直接拦截 | 14,174 条证据，岗位字段与匹配关键结论全部携带证据索引、可回链原文片段 |
| **时间封闭闸门** | 做历史回测时，信号数据与技能词典各自只使用"截止日当时"可用的版本，防止"用今天的知识解释过去" | 839 次回测按此规则执行，回测可信度可审计 |
| **删除项守门** | 判定要删除某能力项但证据不足时，标"待确认"而非静默删除 | 历史切片保留全部错判样本 |
| **预测与事实分离** | 预测引擎产出的是"建议"，进入人工审核队列；LLM 永远不直接写正式数据 | 839 条预测没有一条直接进入岗位版本 |

**最能说明这一点的真实案例**：预测引擎第一版（v1）上线后**低于基线**（方向准确率 0.368 < 平基线 0.449）。我们没有隐瞒这个负结果，而是如实展示并驱动规则 v2 修正——三个预测期一致改进 +5~14 个百分点（但仍逊于基线，也不回避）。**在普遍夸大 AI 效果的环境里，可验证的诚实本身就是差异化。**

### 创新点 3：受治理的智能体运行时与"三层飞轮"

LLM 用得多不叫智能体；**有治理边界的多步智能体**才是。我们的智能体运行时是自研的（不依赖第三方智能体框架），每一步都受四项企业级约束：

1. **每步留痕（审计）**：每次 LLM 调用与工具执行追加写 JSONL 日志（时间戳、Prompt 版本、模型版本、token 消耗、耗时），运行结束落一份可独立读取的摘要。
2. **成本控制**：每次智能体运行设有 token 上限，超限立即终止并留痕，消耗可审计。
3. **工具异常回灌（自纠错）**：工具报错不会崩溃，错误信息回灌给模型让它换路自主修正；错误本身写日志可审计。
4. **结构化输出校验**：最终产物必须通过 Pydantic 强校验，不通就拒绝。

三个智能体跑在同一套运行时上，构成"三层飞轮"，这就是发榜方"效果测评与闭环优化"方向的完整落地：

| 飞轮 | 节奏 | 内容 |
| --- | --- | --- |
| **数据飞轮** | 每天生产 | 技术日报 → 事件抽取 → 涌现扫描 → 新岗位候选自动进入审核队列 |
| **评测飞轮** | 每轮评测驱动 | 评测错误自动聚类 → 分析智能体归纳错误模式 → 规则补丁建议 → 人工审核应用 → 重跑评测对比（负改进如实呈现可回滚） |
| **治理飞轮** | 抽检驱动 | AI 预标注 → 独立复核智能体 → 分歧清单 → 人工裁定回流 |

**真实运转案例（有运行留痕）**：评测飞轮在一轮真实运行中，22 条错误案例被自动归纳为 3 个系统性错误模式、产出 4 条可执行改进建议；分析智能体还**独立发现了预标注自己的两处判断错误**，与另一个独立运行的复核智能体的结论互相印证——同一个 AI 系统的两个智能体从不同入口收敛到一致结论，这是闭环真实生效的直接证明。同一轮中还存在一个小失误（某条规则修复误杀了 3846 条正常数据），评测系统**当场报告"回归 44"**——当天定位修复，这比"修复成功"更有说服力：**系统的评测闭环连自己的错误都能抓住**。

### 创新点 4：涌现岗位自动探测（超出题面举例的发现能力）

题面举例需要一个"新岗位发现"系统，但没有指定要发现哪几个。我们的涌现扫描器是**通用的**：对全部 10,384 条 JD 标题做关键词抽取（英文词组 + 缩写 + 中文连续段），按四条判据自动判定"正在涌现"：

- 近 90 天 JD 数 ≥10 条
- 增长比 ≥1.5 倍
- 标题变体 ≥3 种
- 跨平台分布 ≥2 个

**验证案例：FDE（Forward Deployed Engineer，前沿部署工程师——近两年在头部 AI 公司集中出现的全新岗位）**：2024-01 全部 28 个平台中仅 1 条该类岗位 JD → 2026-08 累计 134 条，被系统自动检出为最高分候选（190 条证据、12 个平台、117 个标题变体），同批自动检出的还有 post training、AI infrastructure、data platform 等 5 个真实涌现方向。**这说明系统能发现题面没提到的岗位，而非只识别一个预设清单。**

### 创新点 5（数据资产，难复刻）：四层时间传导轴 + 五年快照对比

- **四层传导轴**（见创新点 1）：9 年四层时间序列，实证大模型传导周期 70 个月、Prompt 工程 26 个月。这是行业上第一套把"技术从学术到产业"做成可测量指标的中文数据资产。
- **五年快照对比**：通过网页历史存档服务抓取字节/腾讯招聘页面 200 个历史快照（2022-2025），与现行 JD 池对比，16 个岗位 139 项能力变化，**与专家手工五年对比的方向一致**——证明这套自动引擎能复现"专家级"的人工对比结论。

### 技术栈一览

- **后端**：FastAPI 框架（31 个接口），分层架构（业务层 / 领域层 / 基础设施层）
- **前端**：Next.js 26 页面（三工作区），Ant Design 6 基础组件、ReactFlow 图谱
- **持久化**：PostgreSQL 27 张表（事实主库）+ Neo4j（图谱投影，非事实）
- **LLM 接入**：Provider Adapter 设计——不绑定单一模型，通过网关可切换
- **提示词**：统一 YAML 文件管理（含版本号），每次模型调用的输出用强类型校验（Pydantic）
- **评测**：指标由脚本计算生成，每次运行留痕
- **CI**：GitHub Actions 全链绿约 4 分钟

## 4. 测试方案与量化验证

### 4.1 官方硬指标对照

| 官方指标 | 要求 | 实测结果 | 如何复现 |
| --- | --- | --- | --- |
| 岗位 JD 及测试用例 | ≥100 条 | **达标**：180 条冻结测试集（岗位映射 100 + 领域判定 50 + 事件抽取 30），样本清单哈希锁定，不可修改；另有 10,384 条 JD 全量解析库 | `evaluation/samples/manifest.json` |
| 单元测试覆盖率 | ≥60% | **达标 78%**（143 个单元测试 + 30 个 e2e 全部通过） | `make verify`，`--cov-fail-under=60` 强制 |
| JD 解析准确率 | ≥90% | **达标 97%**（97/100，见下文演进故事） | `scripts/evalset.py score` 确定性重算 |

| 人岗匹配准确率 | ≥90% | **达标 100%**（30/30） | 同上 |

### 4.2 岗位映射准确率的提升过程

测试集分三层：**岗位映射**（100 条：给 JD 职位名，判断它属于 46 个标准岗位中的哪一个）、**领域判定**（50 条：判断该岗位是否属于 AI 领域）、**事件抽取**（30 条：技术日报事件字段是否抽对）。每层都用同一个流程：先冻结样本 → AI 给出建议 → 人工逐条确认标准答案 → 系统再作答 → 与标准答案比对得分。指标从起步到终态的完整过程：

```text
78%   起点：AI 预先批量标注的基线（标注者身份在数据中透明记录，与人工判定可区分）
  ↓   规则补丁：产品类岗位名优先、管理岗信号排除、一线部署工程师不再误伤
84%
  ↓   对照实验揭穿评测偏差——修正 15 条偏差后如实回落（诚实优先）
71%
  ↓   语义重判：宽泛岗位名（如"算法工程师"）读取职责原文，细分到多模态/推理/智能体等方向
75%
  ↓   方案对比实验：四种方案在最难的 10 条样本上对照，"先归纳职责、再对照判例"的方案 10/10 全对，验证后回填生产
91%
  ↓   46 条题的标准答案由人工逐条裁决锁定（含 16 条"目录之外、应判为不匹配"）
97%  终态（97/100），每一步口径与依据全部可追溯
```

三个关键设计决策：

1. **主动发现评测自身的缺陷并如实公布**：对照实验暴露了"AI 预标注批量采成标准答案"导致的循环背书（系统订正过的答案被批量为标准答案，指标虚高），修正后指标**主动下调** 13 个点——这不是被动扣分，是修正评测方法论的必然结果。
2. **测试集哈希锁定**，样本一生不变，跨版本对比（`evalcmp.py`）在完全相同的 JD 上重跑，永无样本漂移带来的"虚高"。
3. **46 条最终测试题逐条由人审裁定**（含 16 条"不属任何标准岗位、应输出为空"的题），每条裁决理由（JD 原文 + 双方 AI 意见对比）完整留痕，评测记录只增不改。

### 4.3 评测闭环（可复现）

```bash
evalset.py freeze    ← 冻结样本 + 哈希锁定
  ↓
prelabel.py  →  AI 预标注建议（置信度 + 理由）
  ↓
/tasks 页人工确认 →  annotations.jsonl 逐条追加（带 reviewer_id，append-only）
  ↓
evalset.py score  →  确定性计算 metrics.json
```

评测覆盖范围：每条测试用例都有输入、标准答案、实际输出、判定；错误按 8 类分类统计（同义词未归一化、粒度错误、必备/加分误判、无证据幻觉……）；调优数据与最终测试数据严格隔离；合成数据强制标记 `synthetic=true` 且不计入指标。

### 4.4 历史回测体系

历史回测验证系统"在不知道未来"时能否提前发现技能与岗位变化。每个回测切片遵循：

```text
时间 T：输入只用 available_at ≤ T 的数据
预测：T + 30 / 60 / 90 天
验证：用 T 之后真实发生的后验数据校验
```

回测指标：趋势方向准确率、新技能发现 Precision/Recall、预测提前量（按窗口统计，不全只报最佳案例）、置信度校准、岗位变更命中率。共 839 条回测记录，每次错误类型分类存档（时间泄漏 / 技能归一化错误 / 无证据幻觉等 8 类）。

## 5. 用户体验与部署

### 5.1 三个工作区

系统按使用者角色分为三个工作区，各自覆盖一条完整业务流：

**数据审核区 —— 面向数据审核人员，保证"数据可信"**

数据进入系统先登记来源与许可，经过五道质量门（结构修复、去重、岗位归一、技能归一、证据质量）后进入证据库。审核人员在这里完成两类工作：审核技术日报事件的抽取结果（事件类型、涉及公司、技能提及是否与原文一致）；在评测页面标注定格测试题——页面同时展示 AI 给出的建议判定、置信度和理由，人工确认或修改后提交，每条判定记录标注者和提交时间。审核员看到的每条数据都能点开原始来源（JD 原文、公众号文章原文）。

**企业招聘区 —— 面向招聘负责人与技术负责人，回答"岗位标准是什么、最近变了什么"**

工作台首页按岗位显示"一条最新行动建议"（例如：AI 应用工程师在最近半年新增了 Agent 编排技能的岗位要求，建议确认）。技术负责人进入岗位详情后，看到三栏对比视图（原版本 → 新证据 → 变化说明），每个能力项的增删改都可以逐条展开查看支持它的 JD 原文证据与出现时间；确认后一键发布为新版本。发布后技能图谱自动更新投影。

**求职区 —— 面向求职青年，回答"我和目标岗位差在哪、接下来做什么"**

求职者先选定目标岗位，再通过上传 PDF/Word 简历或手动勾选生成技能画像；系统对照该岗位**已发布版本**输出差距诊断：必备技能缺哪些、加分技能有哪些优势、每项差距按对求职影响排序。每个缺口直接挂在"学练赛证"四段行动上：学什么（对应人社部国家职业标准的知识点）、练什么（实训项目）、赛什么（真实赛事目录）、考什么（真实证书目录）——全部可点击跳转到官方报名/查询页。

**交互与质量**：岗位技能图谱基于 ReactFlow 实现（缩放、拖拽、按能力域钻取到技能点），四个工作台共用同一个"证据抽屉"组件——页面上的任何结论都能展开原始依据。新用户首次进入各工作区有分步引导。上述三条主流程共 30 个端到端自动化用例（Playwright）全部通过。

- **生产**：Railway 云部署（web / api / PostgreSQL 三服务）
  - 前端入口：**https://hiro2.gqy20.top**（自定义域名，当前在线）
  - 后端 API 健康检查：`https://api.hiro2.gqy20.top/health/ready`，实测返回 `status: ok / postgres: ok`
- **本地一键**：`make init` 初始化依赖；`docker compose up -d` 5 分钟内完成本地全量部署。
- **在线核验**：浏览器打开 https://hiro2.gqy20.top 即可沿"求职区诊断 → 招聘区审核发布 → 数据审核区评测标注"完整走一遍。
- **指标重算**：`uv run python scripts/evalset.py score` 一条命令重算全部准确率。
- **持续集成**：GitHub Actions 全链绿约 4 分钟（代码检查 → 单元测试 → 覆盖率 → 构建 → 端到端测试）。
- **交付包**：源码 + Dockerfile/Compose + `.env.example` + 数据库 schema 初始化 + 案例导入数据 + 评测重跑命令。

## 6. 可迁移性与发榜方契合

- **可迁移性**：能力本体（46 岗位 × 30 能力 × 7 分组的专家矩阵）与数据管道按"域"参数化。AI 域之外的大数据、智能系统、物联网三个方向可以用同一套管道扩展，涌现扫描与五道质量门是领域无关的实现。
- **发榜方契合**：
  - **学练赛证**：直接对接科大讯飞 AI 开发者大赛（629 场）、讯飞开放平台认证、华为认证、人社部 1+X 证书等真实目录——与讯飞年报"学练赛证一体化人才培养体系"方向一致。
  - **企业智能体开放生态**：Provider Adapter 多模型接入层，不锁定单一模型，与"开放生态与多模型"方向一致。
  - **合规**：简历授权/脱敏、证据可追溯、AI 辅助决策边界（系统不输出录用/淘汰决定）。
