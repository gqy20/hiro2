# 用户场景

> 产品核心对象是“可信岗位版本”。企业确认岗位标准，人才使用已发布版本诊断能力，审核者维护结论可信度。
> 本文档描述用户如何做决策，不重复技术实现和 API 字段。

## 用户分层

| 层级 | 用户 | 产品角色 | 主要结果 |
| --- | --- | --- | --- |
| 外部 P0 | 企业招聘负责人/技术岗位负责人 | 岗位版本生产者 | 可发布、可解释的岗位标准 |
| 外部 P0 | 新兴领域青年/新就业形态劳动者 | 岗位版本使用者 | 可行动的能力差距和学习顺序 |
| 内部质量 | 数据标注员、领域审核员、评测同学 | 可信度守门人 | 有证据的审核、标注与复核结论 |
| 外部 P1 | 高校就业指导老师 | 聚合观察者 | 岗位趋势和学生群体缺口 |
| 外部 P1 | 企业人才培养负责人 | 培养标准使用者 | 团队缺口、训练任务和能力证明 |

审核与评测是系统支持“人工优化、动态更新、可验证性”的内部流程，不作为与企业和人才并列的市场用户叙事。

## 共同对象

```text
岗位版本 = 岗位名称 + 时间范围 + 必备/加分技能 + 技能点 + 证据 + 审核状态
```

岗位能力以“需求与场景理解 -> 数据与知识处理 -> 智能体与工作流构建 -> 工具与系统集成 -> 效果评测与迭代 -> 部署、运营与治理”组织；工具名称只是能力域下可变化的技能点。

所有用户必须区分：

```text
预测建议 -> 待审核草稿 -> 已发布岗位版本
```

预测建议不能作为正式招聘要求，也不能直接影响人岗匹配。

## 共同页面规则

赛题功能是每个场景的基本盘；可信、动态、可行动的岗位标准是贯穿体验的亮点。岗位发现、版本 Diff、图谱详情和诊断报告都必须在首屏或一次展开内回答：

```text
结论：当前事实或待审核建议是什么？
变化：相对哪个时间窗或版本改变了什么？
依据：哪些来源、原文、样本和审核动作支持它？
行动：它影响哪个岗位版本，用户下一步能做什么？
```

页面不以“模型得分”或长篇 AI 解释作为首要信息；无证据、待审核和已发布三种状态必须显著区分。

## 场景 A：招聘负责人更新既有岗位

### 触发

招聘负责人发现“AI 应用工程师”近期候选人质量不稳定，怀疑当前 JD 已过时，希望更新招聘标准。

### 主路径

```text
选择岗位与两个时间窗
-> 查看新增/删除/修改能力
-> 打开 JD、日报和标准证据
-> 调整必备/加分、权重或等级
-> 提交审核
-> 发布新岗位版本
-> 用新版本发起候选人诊断
```

### 页面重点

- 默认打开当前已发布版本与草稿 Diff。
- 新增、删除、修改固定三列，任何变化可一键打开证据。
- 显示样本量、公司数、时间范围和低置信提示。
- 发布按钮只在审核要求满足时可用。

### 异常与边界

| 情况 | 系统行为 |
| --- | --- |
| 删除项证据不足 | 标记“待确认”，禁止自动删除 |
| 预测建议缺少 JD 验证 | 仅显示为建议，不进入草稿必备技能 |
| 多位审核者意见冲突 | 创建复核任务，保留全部观点 |
| Neo4j 不可用 | 仍可查看岗位版本和 Diff，图谱提示暂不可用 |

### 成功标准

负责人能在一次流程中回答：岗位变了什么、证据是什么、哪版正在生效，以及候选人应按哪版评估。

发布后，负责人可复用同一岗位版本生成招聘 JD 能力模板、候选人诊断标准和培养任务清单。

## 场景 B：招聘负责人定义新岗位候选

### 触发

市场出现“AI Agent 工程师”等职位，但企业尚未形成稳定岗位说明书。该名称只是候选，系统必须证明它与既有岗位存在稳定职责或技能组合差异后才可以发布。

### 主路径

```text
选择领域
-> 浏览新岗位候选
-> 查看技能组合增长、跨公司/跨来源证据
-> 生成定义草稿
-> 编辑名称、职责、必备技能、加分技能、应用场景
-> 提交审核
-> 发布为岗位版本
```

### 页面重点

- 候选列表只显示增长、覆盖、置信度和审核状态，不先展示复杂模型过程。
- 定义编辑器必须包含赛题要求的五要素。
- “为什么不是既有岗位”应有可见对比，而不是模型口头解释。

### 成功标准

系统不只是给岗位起名字，而是提供可编辑定义、区分既有岗位边界，并让每项能力回到证据。

## 场景 C：企业与人才浏览岗位全景和能力阶梯

### 触发

企业需要比较不同技术岗位的能力边界；青年需要选择目标岗位并理解从初级到高级的能力差异。

### 主路径

```text
选择技术栈
-> 选择岗位族与职级
-> 对比岗位能力要求
-> 展开必备/加分技能和技能点
-> 查看岗位版本、时间变化和证据
-> 选择一个已发布岗位版本进入人岗诊断
```

### 页面重点

- 支持 AI、大数据、智能系统、物联网技术栈切换。
- 支持初级、中级、高级/专家级别切换。
- 图谱以技能点为最小可操作粒度，不只展示抽象技能名。
- 版本、时间和证据是岗位节点详情的固定部分。

### 成功标准

用户能够在不阅读技术文档的情况下回答：某岗位不同等级需要什么能力，它与相邻岗位的边界是什么，下一步应该选择哪个岗位版本进行诊断。

## 场景 D：新兴领域青年诊断目标岗位

### 触发

新兴领域青年或新就业形态劳动者准备投递某岗位，希望判断是否值得投递以及应优先补什么能力。

### 主路径

```text
选择已发布岗位版本
-> 上传 PDF/DOCX 或手工录入技能
-> 确认和修正候选人画像
-> 查看多维匹配
-> 查看已具备/部分具备/缺失
-> 获取学习路径
```

### 页面重点

- 首屏先显示关键必备技能是否缺失，而不是夸大的总分。
- 每项判断显示候选人证据和岗位依据。
- 用户修正“精通/了解”或补充项目后，系统重新计算报告。
- 学习路径解释优先级：必备性、岗位权重、前置依赖和当前缺口。
- 路径按“学练赛证”表达：学习知识点、完成项目练习、参与实践评测、沉淀能力证明。

### 异常与边界

| 情况 | 系统行为 |
| --- | --- |
| 简历解析失败 | 保留原文件，提示改为手工录入或重试 |
| 技能无法标准化 | 显示待确认项，不能误计为已具备 |
| 岗位版本过期 | 提示切换到最新已发布版本，保留历史对照 |
| 核心必备技能缺失 | 明确显示“需优先补齐”，不被加分项掩盖 |

### 成功标准

求职者可以理解结果、修正系统错误，并知道下一步学习什么、练什么、如何完成能力证明；系统不输出自动录用或淘汰结论。

## 场景 E：内部质量角色完成数据与预测复核

### 触发

系统运行后自动生成 JD、技能、岗位、证据或预测复盘任务；审核者登录“我的任务”即可开始。

### 主路径

```text
进入我的任务
-> 领取任务
-> 对照原文、系统结果和证据
-> 接受/修改/拒绝/无法判断
-> 提交理由和错误类型
-> 如有分歧进入复核
-> 结果进入评测集、审核记录或质量看板
```

### 页面重点

```text
左：原文与来源证据
中：系统抽取/预测结果
右：人工决策与修正表单
底：时间、run_id、数据集版本、状态
```

审核者不需要下载数据包、阅读 Agent Trace 或理解数据库。该场景服务人工优化、幻觉防控、准确率验证和系统迭代，不作为外部用户主路径。

### 任务类型

| 类型 | 判断内容 |
| --- | --- |
| JD/技能审核 | 职责、必备/加分、岗位、等级和技能映射 |
| 证据审核 | 原文是否支持、来源是否可靠、是否存在冲突 |
| 预测复盘 | 命中、错判、提前量和错误类型 |
| 岗位审核 | 新岗位定义、岗位 Diff 和发布建议 |
| 匹配审核 | 关键短板、部分具备和学习路径 |
| 体验任务 | 是否完成、耗时、卡点、是否相信结论 |

### 成功标准

每条人工反馈都绑定 `case_id`、`run_id`、证据和错误类型，可用于下次回归比较；至少 20% 样本双人独立审核并自动复核分歧。

## 场景 F：高校就业老师观察群体趋势（外部 P1）

### 触发

老师希望了解 AI 相关岗位的能力变化和学生群体的普遍缺口。

### 主路径

```text
选择岗位群与时间窗
-> 查看岗位新增技能与趋势
-> 查看脱敏的群体缺口聚合
-> 导出课程/实训调整建议
```

### 范围边界

不做班级管理、课程管理或学生档案系统。只提供基于已发布岗位版本的聚合观察，且不暴露个人简历。

## 场景 G：企业人才培养负责人设计能力提升任务（外部 P1）

### 触发

企业已确认一个岗位版本，希望将岗位能力标准转化为团队培养和实践任务，而不是只停留在招聘要求。

### 主路径

```text
选择已发布岗位版本
-> 查看团队或候选人群体缺口
-> 按能力链定位薄弱环节
-> 生成学练赛证式训练任务
-> 导出培养任务与能力证明标准
```

### 范围边界

首期只输出训练任务、能力阶梯和证明要求，不做学习管理系统、课程交易或具体认证平台接入。

## 体验验收

所有 P0 场景应满足：

- 用户在首屏知道当前任务和下一步动作。
- 任一结论两次交互内可到达来源、时间和审核状态。
- 预测、草稿和已发布事实视觉上明确区分。
- Loading、空状态、失败和权限不足均有明确解释与下一步。
- 用户任务完成后看到结果、版本或提交状态，而不是静默返回列表。
- 历史回测、预测复盘和模型参数位于可信性/评测区域，不要求企业负责人或青年完成这些操作才能得到岗位结论。
- 人岗诊断呈现当前适配程度、能力差距和提升建议，不呈现自动淘汰或自动录用结论。
